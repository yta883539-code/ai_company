# MVP入出力フォーマット草案

market-research.mdの整理を踏まえ、最小構成(MVP)の入出力フォーマットを草案する。
course-set-pashaと同様、双方向の会話(予約フロー)は不要で、
「作業後メモ→3種類の下書き生成」という単方向のバッチ処理で成立する点がシステム構成上のシンプルさ。
course-set-pashaとの主な違いは、出力1の宛先が(SNS不特定多数ではなく)依頼者本人1名である点。

## 入力フォーマット(業者がLINE/フォームで送る内容)

箇条書きの自由記述を想定。必須項目は無いが、以下の項目があると出力の精度が上がる。

- エアコンの種別・号数(例: 「壁掛け型2.2kW」「お掃除機能付き2.8kW」)
- 分解洗浄の範囲(例: 「フィルター・熱交換器・送風ファンまで分解洗浄」)
- 汚れ状況(例: 「カビ・ホコリ汚れ中程度」「油汚れ強め(キッチン隣接)」)
- 追加施工の有無(例: 「防カビコート施工あり」「消臭コーティングあり」)
- 次回推奨時期の目安(例: 「次回推奨は来年同時期」)
- 施工日
- (任意)施工前後の写真

## 出力1: 依頼者向け作業完了報告メッセージ下書き

- 実施した分解洗浄の範囲(どの部品まで分解したか)を明示する。
- 使用した洗浄剤・追加施工(防カビコート等)の有無を明示する。
- 分解洗浄前後の状態の変化(汚れ具合がどう改善したか)を、入力メモの範囲内で説明する
  (メモに無い効果・効能を推測で付け足さない)。
- 冷媒ガスの取り扱い・電気系統に関する専門的助言は一切行わない旨を徹底する
  (厳守事項として明文化予定)。

## 出力2: お手入れ案内下書き

- フィルターの自己清掃目安(頻度の一般的な考え方)を案内する。
- 次回分解洗浄の推奨時期を、入力メモの「次回推奨」情報があればそれを反映し、無ければ
  一般的な目安(専門的な保証ではない旨を明示)にとどめる。
- 自己分解洗浄のリスクについての一般的な注意喚起(電気系統・冷媒に触れないこと等)を含める。

## 出力3: 簡易な作業履歴記録

- 表形式(施工日/機種系統・号数/汚れ状況/追加施工の有無/次回推奨時期)で1行追記する形。
- course-set-pasha・line-reservation-aiのMVPと同様、当面はスプレッドシート等への手動転記を
  前提とし、専用データベースは持たない。

## 会話フロー・技術構成に関する方針(現時点の仮説)

- 状態管理(予約枠・会話ステージ等)が不要なため、line-reservation-aiのような会話状態マシンは
  不要。course-set-pashaと同様、1メッセージ受信→LLM呼び出し→3種類のテキスト生成→返信、
  という単純な処理で足りる見込み。
- ホスティング基盤はline-reservation-aiで選定済みのGCP Cloud Functions (Python)の知見を
  流用できる可能性が高い。履歴記録(出力3)のみ軽量な保存先(スプレッドシート連携等)で
  足りる見込みで、course-set-pashaのhistory-export-usage-guide.mdの知見をそのまま流用できる
  可能性が高い。
- 実LLM呼び出し・LINE公式アカウントとの接続は、他venture同様APIキー取得・アカウント作成が
  必要でありオーナー承認待ちの範囲。今回は下書き作成支援の設計・フォーマット整理のみに留める。
