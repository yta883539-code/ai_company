# ステップ5(本番運用時のメモ送信)のトーク画面モックスクリプト

## 位置づけ

onboarding-guide.md「次のステップ候補」(フェーズ393・本フェーズ直前の更新分)が
「ステップ5(本番運用時のメモ送信)への同種展開は引き続き次回以降の課題」として残していた
項目に対応する。step1-application-form-mock-script.md(申込フォーム)・
step3-trial-generation-mock-script.md(接続テスト・試験生成)に続き、ステップ5についても
実アカウント名・QRコードを伴わない1往復のトーク例であるため、実LINE API接続(オーナー承認待ち)
を待たずにモックスクリプト化できる。本ドキュメントはその台本であり、実際のLINE公式アカウント・
画像生成は一切行っていない。

## ステップ3との違い

step3は「業者自身が本番送付前に内容を確認するテスト」であるのに対し、ステップ5は
「業者が実際の訪問施工完了後、本番の依頼者へその場で転送する運用」である点が異なる。
このためステップ5のモックでは、(1)試験ではなく実際の施工内容を想定した入力メモ、
(2)onboarding-guide.md 5.が明記する「メモ入力時の留意事項」(厳守事項10、依頼者以外の
第三者の氏名・連絡先等を記載しない)を業者が実際に意識する場面、の2点を追加で示す。

## モック対象ケース

output-samples-validation.mdの`G4_multiple_units_same_visit`(同一訪問先でリビング・寝室の
2台を同時に分解洗浄し、history_rowsが要素数2になるケース。市場調査で複数台セット割引が
業界標準と判明したことを受けて追加されたサンプル)を素材に用いた。`G4_multiple_units_same_visit`
のJSON出力内容(schema/validate_test_cases.py記載)と整合するように、本フェーズで入力メモ文例を
新たに再構成した。新しい事実確認・WebSearch調査は行っていない。

## メモ入力時の留意事項(厳守事項10)が関わる場面の補足

onboarding-guide.md 5.の留意事項は、業者が入力するメモの時点で依頼者以外の第三者(同居家族
以外の来訪者・管理会社担当者等)の氏名・連絡先を記載しないよう求めるものである。上記の例は
依頼者本人の訪問先(リビング・寝室)の情報のみで第三者への言及が無いため、そのまま厳守事項10に
抵触しない例として成立する。第三者が話題に出るケース(例:「管理会社の担当〇〇さんから又来てと
言われた」等)をメモに含めてしまった場合、生成結果にその人物の氏名が含まれないことの確認は
`third-party-personal-info-inclusion-handling-design.md`の厳守事項10自体の検証範囲であり、
本モックスクリプト(画面の見え方の文章化)の対象外として切り分ける。

## 注記・限界

- 上記は output-samples-validation.md の`G4_multiple_units_same_visit`(机上検証・スキーマ
  適合済み、schema/validate_test_cases.py記載のJSON値)の出力フィールド内容をそのまま文面化
  したものであり、実際にLLM APIを呼び出して生成したものではない。実LLM接続後、同じ入力メモに
  対して実際にこの通りの文面が返るかは引き続き未検証(step3-trial-generation-mock-script.md・
  output-samples-validation.md「残る未検証事項」と同じ限界)。
- 本スクリプトは業者向け案内資料(将来のスクリーンショット・操作動画の台本)の素材であり、
  実際の画像・動画の作成、LPやオンボーディングガイドへの画像としての埋め込みは行っていない。
- これにより、step1(申込フォーム)・step3(接続テスト)・step5(本番運用)の3ステップ全てで
  モックスクリプト化が完了した。残るステップ2(友だち追加・連携コード送信)は実アカウント名・
  QRコードを要するため、引き続き実LINE API接続(オーナー承認待ち)にあわせて着手する方針に
  変更はない。
