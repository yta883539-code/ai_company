# ランディングページ ヒーロー画像・アイキャッチ ビジュアル案(フェーズ106)

forklift-pashaフェーズ104・105の「次回候補(2)」(ヒーロー画像・アイキャッチ等のビジュアル案検討)
を受け、landing-page-copy-draft.md・tone-and-manner-guideline.mdを踏まえたビジュアル方向性を
初めて検討する。実際の画像生成・デザイン制作・LPへの実装自体は行わず、方向性の文章化のみに
限定する。

## 前提(既存文書からの制約)

- landing-page-copy-draft.mdのヒーローセクションは「AI・システム」という言葉を使わず、
  「記録を整える手間」のみを主語にしている。ビジュアルも同じ方針を踏襲し、ロボット・チャット
  バブル・未来的なUIモックアップ等の「AIらしさ」を前面に出す意匠は避ける。
- 想定読み手(専任の安全担当者を置かない個人経営・従業員数名規模の倉庫業・運送業・建設業で、
  フォークリフトを1〜数台保有する事業者の経営者・現場責任者)が「自分ごと」として一目で認識
  できる、現場感のある写実的な方向性を基本線とする。
- 点検・検査の実施自体・良否判断は点検者本人の仕事であることが前提(llm-system-prompt-draft.md
  厳守事項1・4)なので、ビジュアルでも「AIが点検している」ように見える表現は避ける(スマホで
  メモを送る動作まではAIの支援範囲内だが、フォークリフトの操作・点検作業自体はあくまで作業者
  本人が行っている構図にする)。

## ヒーロー画像の構図案

```
構図: 倉庫または建設現場でフォークリフトの横に立つ作業者(ヘルメット・安全ベスト着用)が、
      片手にスマートフォンを持ち、点検メモを送っている様子。
視点: 作業者とフォークリフトの両方が分かる、やや引いた斜め俯瞰のミディアムショット。
表現: 写実的な写真調(イラスト調にする場合も過度にデフォルメしない、実在の現場に近い配色・
      質感)。スマートフォン画面に「送信済み」を示す簡易的なチェックマーク程度の軽い演出は
      許容するが、画面内に複雑なダッシュボード・グラフ等は描かない(「記録を整える手間」を
      主語にする方針と矛盾するため)。
配色: 既存のCTAボタン文言「30日間無料で試してみる」等と組み合わせた際に視認性を損なわない、
      現場らしい落ち着いた配色(オレンジ・イエロー系の安全色をアクセントに、背景は倉庫・
      現場らしいグレー・ベージュ系)。
```

## アイキャッチ(SNS・記事サムネイル用)の方向性

- ヒーロー画像とは別に、SNS投稿・記事紹介等で使う正方形〜横長のアイキャッチは、フォークリフト
  の車両番号プレート部分とスマートフォンのメモ入力画面を並置したクローズアップ構図を候補と
  する(課題提起セクションの「車両番号・点検項目・結果をメモで送るだけ」という機能紹介と
  視覚的に対応させる)。
- 複数台保有者向け訴求(課題提起セクション4項目目)に対応するアイキャッチの別案として、
  複数のフォークリフトが並んだ倉庫内に、点検種別(始業前/月次/年次)ごとの期限が近いことを
  示す控えめなアイコン(カレンダー等)を添える構図も候補とする。
