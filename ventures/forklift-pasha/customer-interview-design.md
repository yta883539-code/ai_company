# 想定顧客ヒアリング設計(フェーズ12・初回メモ)

tech-stack.md(フェーズ10)「未検証・残課題」が挙げていた、入力チャネル確定
(LINE Messaging API vs 汎用Webフォーム)のための顧客ヒアリング設計(customer-interview-
design.md相当)に、他venture(aircon-pasha・course-set-pasha・kura-pasha・
line-reservation-ai)で既に用意されている構成(目的の明確化→対象選定→質問項目→実施
方法→留意点)を踏襲して着手する。
※本ドキュメントはヒアリングの「設計」のみ。実際の事業者への連絡・依頼はオーナー許可が
必要なアクションのため、実施可否・実連絡はpending-approval.mdに記録し、ここでは実行
しない。

## ヒアリングの目的

- tech-stack.md「コンポーネント1」が未確定のまま残していた入力チャネル(LINE Messaging
  API vs 汎用Webフォーム/LIFF等)について、倉庫業・運送業・建設業の現場でのLINE公式
  アカウントの業務利用実態を確認する(他venture想定顧客〈美容室・ジム等〉とは業種が
  異なるため、LINE前提を他venture同様にそのまま踏襲してよいかの検証)。
- pricing-plan.mdの3プラン(ライト980円/1台・スタンダード2,480円/3台・複数台4,980円/
  10台、保有台数主軸の設計)が、実際の倉庫業・運送業・建設業事業者の保有台数分布・支払い
  意欲と合致するかを検証する。
- mvp-flow-draft.mdの点検種別3区分(daily/monthly/annual)の分類・入力例が、現場の点検者
  にとって迷いなく区別できる粒度かを確認する(特にdaily〈始業前点検〉とmonthly〈月次
  自主検査〉の違いが、点検者の実務感覚と一致するか)。
- llm-system-prompt-draft.mdの厳守事項3(annual区分で検査業者名が欠落した場合は
  status=insufficient_input)が、実際の特定自主検査の現場運用(検査業者から口頭で結果
  だけ伝えられ、業者名を点検者が把握していない場面がないか等)と衝突しないかを確認する。
- daily区分の入力頻度が月20〜25回/台(pricing-plan.md前提)と高いことを踏まえ、始業前
  点検のたびにメモ入力する運用が現場の実作業フローに乗るか(忙しい朝の時間帯に入力の
  手間が負担にならないか)を確認する。

## 対象(仮)

- フォークリフトを1〜3台程度保有する個人経営・小規模の倉庫業(資材置き場・物流拠点) 3〜4件
- フォークリフトを保有する運送業者(トラック運送業で構内作業用に保有するもの) 2〜3件
- フォークリフトを保有する建設業者(資材置き場・現場構内での使用) 2件

合計7〜9件前後を目安とし、業種(倉庫業・運送業・建設業)と保有台数(1台/複数台)の両方で
回答の分散を確保する。他venture同様、interview-candidate-selection-criteria.md相当の
選定基準の明文化・ロングリスト作成は次のステップ候補とする(本フェーズでは質問項目設計
までに留める)。

## ヒアリング項目(質問案、全12問)

### A. 現状把握
1. フォークリフトの始業前点検・月次自主検査・特定自主検査は、現在どのように記録して
   いますか?(紙の点検表、Excel、記録していない、など)
2. 点検記録の作成・保存(3年保存義務)に、1回あたり・1ヶ月あたりどのくらいの手間を
   感じていますか?
3. 特定自主検査(年次)は登録検査業者に依頼していますか?その際、検査業者名・結果を
   自社の記録に残す作業は誰が・どのように行っていますか?

### B. 入力チャネルの検証(tech-stack.md未確定事項)
4. 業務でLINE公式アカウントを使ったやり取り(取引先・協力会社との連絡等)はありますか?
   始業前点検のたびに、スマートフォンのLINEでメモを送る運用は現場の実態に合いますか?
5. LINEよりも、ボタン選択中心の簡単なWebフォーム(車両番号を選ぶ→点検項目にチェック、
   程度)の方が、朝の忙しい時間帯の入力として受け入れやすいと感じますか?
6. 点検は点検者本人のスマートフォンから行いますか、それとも事業所に戻ってから事務担当者
   がまとめて入力する運用の方が実態に近いですか?

### C. 価格感覚・分類粒度の検証
7. pricing-plan.mdの3プラン(ライト980円/1台、スタンダード2,480円/3台、複数台4,980円/
   10台)を提示した場合、自社の保有台数に近いのはどのプランですか?月額としてこの価格
   感は受け入れやすいですか?
8. 始業前点検(daily)・月次自主検査(monthly)・特定自主検査(annual)の3区分は、点検
   記録をつける際に迷わず区別できる分類だと感じますか?
9. 特定自主検査の結果を記録する際、検査業者名を毎回把握・記載していますか?業者から
   結果のみ口頭で伝えられ、業者名を点検者側で記録していない場面はありますか?
   (厳守事項3の現場適合性の確認)

### D. 導入障壁の確認
10. 無料トライアル(初回生成から30日間、またはcourse-set-pasha等と同様の生成○回到達の
    いずれか早い方、クレジットカード登録不要)という条件は始めやすいと感じますか?
11. これまで点検記録の電子化・デジタル化を検討したことはありますか?検討した場合、
    何が導入の障壁になりましたか?(価格、操作の複雑さ、現場の抵抗感など)
12. 複数の点検者(複数の運転者)がいる場合、点検者ごとに入力してもらう運用と、点検
    担当者1名がまとめて入力する運用のどちらが実態に近いですか?

## 実施方法(案)

- 形式: 他venture(line-reservation-ai・course-set-pasha等)と同様、対面ではなくオンライン
  (電話・LINE・Googleフォーム)を基本とし、現場作業の合間でも回答しやすくする。
- 所要時間: 1件あたり10分程度を目安とする(質問数12問、他ventureの14〜17問より少なめに
  設計し、現場作業者の負担を抑える)。
- 謝礼: 有償の謝礼は行わず、ヒアリング協力者には正式リリース時の先行招待・割引を案内する
  想定(実施の可否・内容はオーナー判断が必要)。

## 実施にあたっての留意点(pending-approval対象)

- 実在の事業者への連絡(電話・LINE・DM・メール等)は「外部への送信・連絡」に該当するため、
  本エージェントの権限では実行しない。誰にどう連絡するかの具体案(対象ロングリスト・連絡
  文面)はオーナー承認が得られた段階で別途作成し、pending-approval.mdに記録する。

## 未検証の仮説(要検証)

- 質問12問が10分に収まるか(実施前にline-reservation-aiのinterview-rehearsal-script.md
  のようなリハーサル台本での時間計測が必要。次回候補とする)。
- 業種(倉庫業・運送業・建設業)によって、LINE業務利用率・入力チャネルの好み(質問4〜6)に
  明確な差が出るか。差が大きい場合、入力チャネルを業種別に分ける必要が出てくる可能性が
  ある。
