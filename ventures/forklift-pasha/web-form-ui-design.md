# Webフォームのボタン選択・プルダウン中心のUI詳細設計(フェーズ71)

tech-stack.mdフェーズ70で入力チャネルを汎用Webフォーム(LINE非依存)に暫定決定した際の
「未検証・残課題」に挙げた、daily区分(始業前点検、月20〜25回/台と利用頻度が高い)の
入力負荷低減を主眼としたUI詳細設計。schema/output.schema.jsonのinspection_record各
フィールドに対応する入力項目を、自由記述からボタン選択・プルダウン中心に置き換える方針を
具体化する。机上設計であり実際のフォーム実装・実顧客での操作感検証は未着手。

## 設計方針

- 点検種別(daily/monthly/annual)ごとに入力頻度・入力者の状況が大きく異なるため、
  1つの汎用フォームではなく**区分別に入力画面(URL)を分ける**。点検者は普段使う区分の
  URLをブックマーク/ホーム画面に追加しておけば、毎回のメニュー選択操作自体を省略できる。
- schema側のtypeフィールドはURL(どの区分の画面から送信されたか)で自動的に決まるため、
  点検者がtypeを選択する操作そのものを発生させない(厳守事項2「推測で埋めない」は
  フォーム側で区分が確定済みのため抵触しない)。
- 自由記述が必要な項目(items・result)は、daily区分では「よくある記載」をボタンで
  選べるようにしつつ、ボタンにない内容は自由記述欄に追記できる形で両立させる
  (ボタンのみに限定すると、異常時の具体的な記述ができなくなるため)。

## daily区分(始業前点検)の入力画面

高頻度入力のため、タップ数最小化を最優先する。

1. **車両番号**: プルダウン(事業者が保有する車両をあらかじめ登録、vehicle_idに対応)。
   保有台数が少数(1〜数台)という想定顧客像(README記載)に合わせ、プルダウンではなく
   「車両ボタンを並べて1タップで選択」する方式でも台数が少なければ成立するため、
   保有3台以下はボタン表示・4台以上はプルダウンに切り替える表示分岐を採用する。
2. **点検結果の一次選択**: 「異常なし」ボタンと「異常あり」ボタンの2択をまず提示する。
   - 「異常なし」を選んだ場合、安衛則第151条の25の点検項目(ブレーキ・警告灯・異音・
     油圧・タイヤ・フォーク等、market-research.md記載の一般的な点検項目を参考に
     チェックリスト化)を**デフォルト全チェック済みのトグル一覧**として表示し、
     該当しない項目があれば個別にオフにできるようにする(resultは「異常なし」、
     itemsはチェック済み項目名をカンマ区切りで自動結合)。
   - 「異常あり」を選んだ場合は、チェックリストを初期状態は全てオフにし、異常が
     あった項目をオンにしたうえで、各項目に対応する自由記述欄(「どう異常だったか」)
     を表示する(resultは「異常あり」、itemsはオンにした項目名+自由記述を結合)。
     厳守事項1(AIが独自に安全性評価を追記しない)との整合のため、自由記述欄は
     点検者本人の記述をそのまま転記する前提を画面上にも明記する。
3. **点検者名**: 前回送信時の入力値をブラウザのlocalStorage相当にキャッシュしておき、
   デフォルト値として表示する(都度入力の手間を省く。変更があれば上書き可能)。
4. **実施日**: デフォルトで本日の日付を自動入力(dateフィールド)。前日分の後追い入力等、
   変更が必要な場合のみ日付ピッカーで変更する。
5. 送信ボタンは1つのみ。上記1〜4が揃えば送信可能(insufficient_inputに該当する
   車両番号・点検種別・実施日の欠落は、車両番号必須選択・typeはURL確定・実施日は
   デフォルト値ありのため、daily区分では構造的に発生しにくい設計とする)。

### 想定タップ数(異常なしの場合)

車両ボタン選択(保有3台以下)→「異常なし」ボタン→送信、の3タップで完了する想定。
チェックリスト・点検者名・実施日はデフォルト値をそのまま使う前提。実際の操作感は
実装・実顧客検証(承認待ち)で確認が必要。

## monthly/annual区分の入力画面

daily区分と異なり月1回・年1回の低頻度入力のため、入力負荷低減よりも記載の正確性を
優先し、daily区分よりも自由記述欄を多めに残す。

- **monthly**: 車両番号(daily同様のボタン/プルダウン)、点検者名(デフォルト値あり)、
  実施日(デフォルトは本日)、点検項目・結果(自由記述。月次自主検査は項目数が多く
  チェックリスト化の是非は別途検討が必要なため、本フェーズではdaily区分のみ
  チェックリスト化し、monthlyは次回候補とする)。
- **annual**: monthly同様の構成に加え、inspector_company(検査業者名)を必須の
  自由記述欄として表示する。検査業者名はdaily区分の点検者名と異なり事業者側で固定の
  候補が限られる可能性があるため、プルダウン化(よく使う検査業者を事前登録)も
  将来的な改善候補とするが、本フェーズでは自由記述のまま据え置く。

## 画面遷移・ナビゲーション

- 3区分それぞれのURLへのリンクを並べたトップページ(事業者ごとの固有URL想定)を設け、
  点検者は自分が行う点検種別のリンクを選ぶ。dailyのリンクを最も目立つ位置(先頭)に
  配置し、高頻度区分へのアクセスを最短にする。
- 送信完了後は、整形済みテキスト(inspection_record.body)をその場で画面表示し、
  点検者がコピーしてスプレッドシートに貼り付けられるようにする(mvp-flow-draft.md
  出力1の想定用途に対応)。reminder_notice非nullの場合は同画面に併記する。
