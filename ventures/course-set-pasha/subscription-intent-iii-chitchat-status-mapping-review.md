# 厳守事項7a(iii)雑談ケースのstatusマッピング机上検証(2026-09-13 02:00 UTC)

## 位置づけ

llm-system-prompt-draft.mdの「次の課題」(2026-08-15 05:00 UTC追記)
「厳守事項7aの境界(特に(iii)雑談と(iv)判断不能の切り分け)は机上での言い回し例に基づく
仮の線引きであり、実LLM接続後に実際の入力文でどちらに判定されるかの検証が必要」のうち、
実LLM接続(オーナー承認待ち)を要しない範囲、すなわち「(iii)雑談と判定した場合に
`status`enumのどの値に帰着させるべきか」を机上で確定させ、テストケースとして固定する。

schema/output.schema.jsonの`status`フィールド説明には既に「厳守事項7a(iii)(雑談の域を
出ない表現)は解約意図として扱わず、既存のgenerated/out_of_scope/insufficient_inputの
いずれかに帰着させる」と記載済みだったが、実際に3値のうちどれに帰着するかを示す
テストケースがCI1〜CI3(いずれも(i)(ii)(iv)相当)には存在せず、schema/validate_test_cases.py
上で(iii)の挙動を検証できていなかった。

## 検討

(iii)は「契約継続には触れず、利用頻度・満足度についての雑談・愚痴の域を出ない表現」と
定義されており、これ自体は独立したstatusを持たず、入力メモの他の内容次第で以下のいずれかに
帰着する。

- 雑談的な一言のみで、エリア名・本数など課題入れ替えメモとして必要な情報が一切含まれない
  場合(例:「最近あんまり使えてないな〜(笑)」のみ) → 会員管理・予約受付・決済の話題
  ではなく単なる感想表明であり、厳守事項7の定型対象外案内(out_of_scope、「会員管理・
  予約受付・決済のご案内はできません」)を返すのは論旨がずれる。実質は「課題入れ替え
  メモとして扱うには情報が不足している」状態であるため、`insufficient_input`に帰着させ、
  厳守事項8の再送依頼文言(エリア名・本数を尋ねる)を返す。
- 雑談的な一言に加えて、実際の課題入れ替え内容(エリア名・本数等)も同じメモ内に含まれて
  いる場合(例:「最近あんまり使えてないけど、エリアAに新着課題8本追加したよ」) →
  雑談部分は解約意図として扱わない(厳守事項7a(iii)の主旨)一方、課題入れ替え内容自体は
  通常どおり抽出できるため`generated`として3出力を生成する。雑談部分(「最近あんまり
  使えてないけど」)は出力1〜3のいずれにも反映しない(告知文・記録は課題入れ替え内容の
  みを扱う既存の厳守事項1〜6の対象外)。

## 結論・対応

- 上記2パターンをそれぞれ`insufficient_input`・`generated`としてschema/validate_test_cases.pyに
  新規テストケース(CI4・CI5)として追加する。
- llm-system-prompt-draft.mdの厳守事項7a(iii)本文に、上記の帰着先の判断基準
  (課題入れ替え情報の有無で`insufficient_input`/`generated`のいずれかに帰着する旨)を
  追記する。

## 残る未検証事項

- 実際のLLMが「雑談」と「(iv)判断不能」をどう切り分けるか自体(言い回しの微妙な違いに
  対する分類精度)は、引き続き実LLM接続後(オーナー承認待ち)の検証が必要。本ファイルは
  あくまで「(iii)と判定された場合の帰着先」という机上で決定可能な範囲にとどまる。
