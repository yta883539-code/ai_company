# セッター複数プランにおける「複数セッターでの共同利用」実現方式の検討・明確化(フェーズ204)

作成日: 2026-09-11(フェーズ204)

## 背景・気づいたギャップ

pricing-plan.md(フェーズ5)のプラン表で、セッター複数プランの想定顧客像を「複数ジムを
掛け持ちするフリーランスセッター、複数店舗を運営する事業者」と記載している。実装・顧客向け
コピーを確認したところ、この2つの顧客像で前提としている技術的な仕組みが異なることに気づいた。

- 「複数ジムを掛け持ちするフリーランスセッター」: 1人のセッターが複数ジムを掛け持ちする
  ケース。line-user-id-linking-design.md(フェーズ77)のとおり1つのLINE user_idに対し
  gym_area_pairsで複数ジム/エリアを登録できる設計であり、既に実現済み。
  landing-page-copy-draft.mdのFAQ「複数のジムを掛け持ちしているセッターですが、1人で
  使えますか?」の想定にも一致する。
- 「複数店舗を運営する事業者」: 文言だけを読むと、複数の異なるスタッフ(セッター)がそれぞれ
  自分のLINEアカウントから送信し、1つの契約(サブスクリプション)の利用枠を共有するケースを
  連想させる。しかし現在の設計はuser_profile/{user_id}(application-form-submission-flow-
  design.md・checkout-session-plan-selection-design.md)を単位としてplan・gym_area_pairs・
  利用回数カウンタを保持しており、「1つのuser_id = 1契約」が前提。複数の異なるuser_idが
  1つの契約・利用枠を共有する仕組みは存在しない。

つまり「複数店舗を運営する事業者」がスタッフ各自のLINEアカウントから独立して送信したい場合、
現行設計ではサポートできない(スタッフごとに別々の契約が必要になってしまう)。

## 検討: 複数user_id対応が必要か

kura-pashaのcraftsman-account-linking-design.md・contractor-transfer-design.mdのように
複数メンバーが同一契約を共有するworkshop型の設計を横展開することも技術的には可能だが、以下の
理由でMVP範囲では見送り、運用でカバーする方が本ventureの特性に合っていると判断する。

- 本ventureは単方向バッチ処理(1メッセージ受信→3種類のテキスト生成→即返信)であり、
  「誰が送ったか」を区別する必要が業務要件上存在しない(生成される投稿文・告知文の宛先は
  ジム全体であり、送信者個人を宛てた文面ではない)。契約者と後継者を明確に区別する必要がある
  kura-pashaの業態とは異なる。
- 複数店舗運営事業者であっても、実務上は「店舗ごとに1台の業務用スマートフォン・共有タブレット
  で公式LINEアカウントを開き、その場にいるスタッフが入力する」運用が小規模事業者では一般的
  (line-reservation-ai等の他ventureでも同様の想定)であり、1つのLINEアカウント(=1つの
  user_id)を店舗の複数スタッフで共有利用する形で十分に「複数セッターでの共同利用」という
  ニーズを満たせると考えられる。
- 複数の異なるuser_idを1契約に束ねる設計は、workshop的な抽象化・招待コードフロー・契約者
  概念の追加が必要になり、単方向バッチ処理という本ventureの単純さを損なう。実需要が確認
  できていない段階での先行実装はオーバーエンジニアリングにあたる。

## 結論・スコープ確定

- MVPでは「複数セッターでの共同利用」を「1つのLINEアカウント(1 user_id)を店舗・チーム内の
  複数スタッフで共有して使う」運用と定義する。技術的な追加実装は不要(既存のuser_profile/
  {user_id}単位の設計のまま)。
- pricing-plan.mdの想定顧客像の記載はミスリーディングになり得るため、前提を明記する訂正を
  行った(本フェーズで対応済み。下記「対応した内容」参照)。
- 将来、複数の異なるLINEアカウントでの共同利用の実需要が顧客ヒアリング等で確認された場合は、
  kura-pashaのworkshop型設計(craftsman-account-linking-design.md・contractor-transfer-
  design.md)を参考に横展開を検討する。

## 対応した内容(本フェーズ)

- pricing-plan.mdのセッター複数プラン行の想定顧客像を「複数店舗を運営する事業者(1つの
  LINEアカウントを店舗内で複数スタッフが共有運用する前提)」に更新した。
