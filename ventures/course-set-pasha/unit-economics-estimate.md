# ユニットエコノミクス試算(決済手数料・Firestore原価・LLM API原価の統合)

作成日: 2026-08-17

## 背景

これまで本ventureの原価構造は、pricing-plan.md(月額サブスク料金・従量単価)を起点に、
subscription-billing-cost-estimate.md(決済手数料+Firestore読み書き原価)と
llm-api-cost-estimate.md(LLM API原価)の2ファイルに分かれて個別試算されてきた。
いずれも「単体では月額料金に対して小さい」という結論だったが、3つのコスト要素を
1オーナーあたり月次で合算した最終的な粗利率はまだ提示していなかった。line-reservation-ai/
unit-economics-estimate.mdが果たした役割(複数の個別試算を横断して事業性を定量化する)を
本ventureでも行い、価格設定(pricing-plan.md)の妥当性の最終確認材料とする。

## 前提

- 対象は3プラン(ライト1,980円/8回、スタンダード3,480円/15回、セッター複数5,980円/30回)
  のうち、含まれる生成回数を毎月使い切る(超過なし)ケースとする。超過課金分は
  subscription-billing-cost-estimate.mdの「超過課金分の決済手数料試算」節に既存の試算が
  あるため本試算では扱わない。
- 決済手数料: subscription-billing-cost-estimate.mdの試算(クレジットカード継続課金
  4.3%仮定。基本手数料3.6%+Stripe Billing追加手数料0.7%、2026-09-14 22:00 UTC
  WebSearch調査による更新後の値)をそのまま使用。
- Firestore原価: 同ファイルの試算により「月間生成回数の上限まで使い切っても無料枠内に
  収まり、実質0円」と結論済みのためそのまま0円として扱う。
- LLM API原価: llm-api-cost-estimate.mdのSonnet 5・シナリオB(現行ドラフト文字数からの
  上限側概算)の2ケースを採用する。
  - キャッシュなし: 1回あたり約8.91円
  - プロンプトキャッシュ利用時(1時間TTL採用を仮定、実装時の課題として残存): 約3.26円
- いずれも机上の概算であり、実LLM接続・実決済代行サービス契約はオーナー承認待ちの範囲。

## 結論

- 最も保守的な組み合わせ(プロンプトキャッシュ未導入・シナリオB上限)でも、3プラン
  いずれも粗利率91.2〜92.1%を確保できる見込みで、決済手数料単独(月額に対し一律4.3%、
  2026-09-14 22:00 UTC改訂)・LLM API原価単独(キャッシュなしで月額の約3.6〜4.5%程度)が
  それぞれ小さいという既存の個別結論を合算しても、事業性を揺るがす水準にはならないことを
  定量的に確認できた。
- プロンプトキャッシュ(1時間TTL)を導入できれば粗利率はさらに94.1〜94.4%まで改善する。
  週2〜3回という想定利用頻度(sns-tone-research.md)ではデフォルトTTL(5分)だと
  キャッシュヒットしにくいため、llm-api-cost-estimate.mdが既に指摘した「1時間TTL採用」の
  優先度が本試算でも裏付けられた。
- プラン間で粗利率にほぼ差がない(91.2%〜92.1%の範囲に収まる)ことから、pricing-plan.mdの
  従量単価設計(上位プランほど単価を下げる)は粗利率を大きく損なわずに上位プランへの
  誘導・ヘビーユーザー割引を両立できていると確認できた。

## 残課題(新規)

- 上記はいずれも「含まれる生成回数をちょうど使い切る」ケースの試算であり、実際の利用分布
  (上限未満で終わるオーナーが大半か、超過が常態化するオーナーが一定数いるか)は実測データが
  ないため不明。実LLM・実決済接続後の利用実績を踏まえて再試算が必要。
- 決済手数料4.3%(2026-09-14 22:00 UTC改訂: WebSearchによる複数の独立した二次情報での
  確認は得たが、Stripe公式サイトへの直接アクセスは実行環境の制約〈egress proxyによる
  ブロック〉でできなかったため公式一次情報での確認はまだ済んでいない)・キャッシュ
  有効期限1時間TTLはいずれも実装着手時に契約前の最終確認が必要(subscription-billing-
  cost-estimate.md・llm-api-cost-estimate.mdの既存の残課題を踏襲)。
- 本試算には将来的な人的サポートコスト(オンボーディング・問い合わせ対応)を含めていない。
  llm-api-cost-estimate.mdの結論と同様、これは原価試算の範囲外(人件費)のため別途整理が必要。
  → support-cost-estimate.md(2026-09-15新規)で運営者自身の対応工数を時間ベースで粗く
  試算した(1顧客あたり初月30分・2ヶ月目以降月10分程度、時給3,000円の未検証仮定で
  月500〜1,500円相当)。現金支出コストではなく機会費用のため本試算の粗利率自体は不変だが、
  スケール時の対応可能顧客数の目安(粗い試算で運営者1人あたり約120顧客)を新たに示した。
  時給換算・対応時間はいずれも実顧客対応後の再検証が必要な仮定にとどまる。
