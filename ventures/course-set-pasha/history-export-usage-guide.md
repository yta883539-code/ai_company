# 課題入れ替え履歴のスプレッドシート転記手順(運用ガイド)

`prototype/history_export.py`の`history_rows_to_csv_text()`が生成するCSVテキストを、
オーナーが実際にスプレッドシート等へ手動転記する際の運用手順を整理する。
mvp-flow-draft.mdの出力3(課題入れ替え履歴の簡易記録)は当面専用データベースを持たず、
この手動転記運用を前提とするため、手順自体をここで文書化しておく。

## 前提

- MVPの段階では、システムがLINE/フォームへの返信メッセージ本文の中に
  「履歴記録用CSV」としてこのCSVテキストをそのまま貼り付けて送る想定
  (システムプロンプト側でその旨を明示する必要があり、これはllm-system-prompt-draft.md側の
  今後の課題として別途扱う)。
- CSVはヘッダー行(改訂日/エリア/テープ色・グレード帯/本数/特徴キーワード)付きで、
  区切り文字はカンマ、改行は`\n`。日本語フィールド(エリア名・特徴キーワード等)を含むため、
  値にカンマや改行を含む場合はPythonの`csv`モジュールの標準仕様に従いダブルクォートで
  囲まれる。

## 手順(オーナー側の作業)

1. LINE/フォームに届いた返信メッセージ本文から、「履歴記録用CSV」の見出し以降の
   テキストブロックをまとめて選択してコピーする。
2. Google スプレッドシート(または Excel)の対象シートを開き、既存の最終行の
   1つ下のセル(A列)を選択する。
3. 「値だけ貼り付け」ではなく通常の貼り付け(Ctrl+V / Cmd+V)を行う。使用環境によって挙動が
   異なるため、以下のいずれかで対応する。
   - **Google スプレッドシート(ブラウザ版)**: カンマ区切りテキストの貼り付け時に自動的に
     列分割される。追加の区切り操作は不要。
   - **Google スプレッドシート(モバイルアプリ版)**: ブラウザ版のような自動列分割は行われず、
     「テキストを列に分割」メニュー自体も存在しない。CSVテキストがA列1セルにそのまま入るため、
     隣接セルに`=SPLIT(A1,",")`を入力して展開する(貼り付け先がA列以外の場合は式内の参照先を
     読み替える)。
   - **Excel**: 直近で「データ」→「区切り位置」(Text to Columns)をカンマ区切りで一度でも
     実行した実績がある環境では、以降の貼り付けで同じ区切り方が自動適用される。実行したことが
     ない環境(初回利用時など)では自動分割されずカンマ区切りのまま1セルに入るため、貼り付け後に
     手動で「データ」→「区切り位置」→「カンマ」を選択して区切る。
4. 貼り付け後、1行目(ヘッダー行)が重複していないか目視確認し、重複していれば削除する
   (既存シートに既にヘッダー行がある前提のため、2回目以降の貼り付けではヘッダー行を
   除いた2行目以降のみをコピーするのが望ましい)。
5. 「未記入」(改訂日不明)・「不明」(本数不明)というプレースホルダーが入っている行が
   あれば、元のLINEメッセージ本文を見返して手動で補完するか、そのまま「後で確認」の
   目印として残す(history_export.pyはあくまで未確認項目を可視化するだけで、
   自動補完は行わない設計)。

## 既知の限界・今後の課題

- 現状はコピー&ペーストの手作業を前提としており、Google Sheets APIによる自動追記は
  行っていない(API連携は外部サービスとの接続であり、着手にはオーナー承認が必要な範囲)。
- 複数エリアを一度に改訂した場合(history_rowsが複数要素)、CSVは複数行になるため、
  貼り付け時にシートの既存行を上書きしないよう、貼り付け先セルの位置(最終行の1つ下)を
  毎回確認する必要がある旨を手順3に明記した。誤操作防止のため、将来的には貼り付け前に
  「最終行+1」のセルをハイライトする案内文をLINE返信メッセージに含める改善案がある。

## 追記(2026-08-08 20:00 UTC): モバイルアプリ版・Excelでの挙動をweb調査で確認・手順に反映

上記で「未検証」としていたステップ3の自動列分割の挙動について、公開情報(Google公式ヘルプ・
一般的な解説記事)の範囲でweb調査し、判明した内容を手順3に反映した(ブラウザ版/モバイル
アプリ版/Excelの3パターンに分岐)。要点は、Googleスプレッドシートのモバイルアプリ版には
自動列分割機能が無く`SPLIT`関数での代替が必要なこと、Excelは環境の操作履歴に依存する
「学習型」の挙動であることの2点。実際にオーナーがどの環境を使うかが判明した際は、該当する
パターンの手順のみを案内すればよい状態になった。
