# グッズ列参加有無 入力フィールド設計

README.mdフェーズ52(input-output-sample-mapping.md作成時)で発見した設計ギャップ(2)
「『グッズ列に並ぶか否か』を受け取る入力フィールドが現行の入力フォーマットに存在しない」
(入力サンプルN4で発覚)への対応方針を検討する。

## 1. 課題

README.md「概要」節の入力定義は「当選公演の会場・日時・枚数、予算感、現地でのグッズ購入希望
(発売形式・個数上限等)、前後の予定」としており、「グッズ購入希望」はグッズそのものの
購入意欲(発売形式・個数上限)のみを指し、「開場前のグッズ列に並ぶかどうか」という行動選択
は別概念として未定義だった。day_timetable(出力2)はREADME.md出力定義上「開場・グッズ列を
踏まえたもの」とされているが、グッズ列に並ぶ意思がない利用者にまで並び目安を提示すると
不要な情報になり、並ぶ意思がある利用者には現行入力だけでは「何時集合を目指すべきか」の
判断材料(並ぶ意思の有無)が欠落する。

## 2. 設計方針

- 入力メモに新フィールド`goods_line_intention`を追加する。値は`join`(並ぶ)/`skip`
  (並ばない)/未記載(言及なし)の3通りを想定する。
- 未記載の場合は、他の入力フィールド同様に「不足」とは扱わず(README.md出力定義の
  `insufficient_input`はこれまで会場・日時・枚数等の必須項目のみを対象としており、グッズ列
  参加有無は元々任意情報という位置づけを維持する)、day_timetableのグッズ列関連の記述を
  「グッズ列に並ぶかどうかは入力メモに記載がなかったため、並ぶ場合は早めの到着を検討する
  一般的な目安を補足する」という両論併記の一言に留める。
- `join`が明記された場合のみ、day_timetableに「グッズ列に並ぶ場合の目安到着時刻」の行を
  明示的に1件追加する(開場時刻からの一般的な前倒し目安。venue-master-draft.mdに実際の
  グッズ列集合場所・待ち時間データは収録されていないため、具体的な分数の提示ではなく
  「開場より前に到着することを検討する」という一般論に留め、実際の行列状況の保証は行わない
  ことを明記する)。
- `skip`が明記された場合は、day_timetableからグッズ列関連の行を省略し、開場時刻を基準とした
  入場目安のみを示す。

## 3. スキーマへの影響

- schema/output.schema.jsonの出力側(day_timetable配列の各要素`time_label`/`action`)は
  既存の自由記述構造のままで対応可能であり、出力スキーマの構造変更は不要と判断した
  (内容面の生成ルールの変更であり、フィールド追加は入力側のみ)。
- 入力側はREADME.md「概要」節の入力定義の文言を更新し、「現地でのグッズ購入希望(発売形式・
  個数上限等)」の次に「グッズ列に並ぶかどうかの意向(任意)」を追加する想定。実際の
  README.md本文更新・llm-system-prompt-draft.mdの生成ルール反映は次回以降に行う(本ドキュメント
  では方針決定のみ)。

## 4. 残課題・次回候補

- README.md「概要」節・llm-system-prompt-draft.mdへの本方針の反映(`goods_line_intention`の
  3値分岐ルールの明文化)。
- input-output-sample-mapping.mdのN4ケースについて、本方針に基づいた期待出力(day_timetableの
  グッズ列行の有無)の確定・サンプル更新。
- 設計ギャップ(1)複数会場「ハシゴ」対応・(3)チャット代等の取り扱い、は本ドキュメントの
  対象外として次回以降に持ち越す。

実装・外部サービス接続は一切行っていない。承認が必要なアクション(支払い・アカウント作成・
外部公開・送信等)は発生していないためpending-approval.mdへの追記なし。
