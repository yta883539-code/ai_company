# 特定商取引法に基づく表記・プライバシーポリシー 文面草案(フェーズ29)

README.mdフェーズ28(venue-alias-input-text-logging-design.md)で判明した残課題「プライバシー
ポリシー(legal-notices-draft.md相当のドキュメント)がoshien-pashaにはまだ整備されていない」
に対応し、line-reservation-aiのlegal-notices-draft.mdの構成を本venture固有の前提
(会員登録なし、Web単体・LINE非依存、都度プラン/月額フリーパスの2プラン)に合わせて整理する。

**本ドキュメントは草案作成のみを行うものであり、実際のLP公開・外部への表示は一切行わない。
公開そのものはオーナー許可が必要なアクションのためpending-approval.mdに別途記録する。**

## 前提・未確定事項

以下は本サービスの運営主体(個人事業主として営むか法人化するか、屋号、所在地、連絡先等)が
まだ確定していないため、実際の掲載時にはオーナー自身の実情報での埋め込みが必須。本草案では
該当箇所を`【要記入】`として明示する。

都度プラン・月額フリーパスいずれの決済代行サービスも、payment-method-design.md(フェーズ5)で
Stripe Checkout(`mode=payment`/`mode=subscription`の分岐生成)に確定済みである。未着手なのは
実Stripeアカウントの開設・本番APIキー取得(オーナー承認待ち)のみ。

他6venture(line-reservation-ai等)と異なり、本serviceはLINE公式アカウントを前提としない
Web単体構成(payment-method-design.mdフェーズ5)であるため、以下の草案は「LINE友だち追加」
を前提とした記述を含めず、Webサイト上での利用に合わせた記述とする。

## 1. 特定商取引法に基づく表記(案)

本サービスは都度課金または月額課金のSaaS(役務提供)であり、通信販売の「商品」の売買では
ないが、継続的な役務提供契約(月額フリーパス)・単発の有償サービス提供(都度プラン)として
特定商取引法の表示義務(通信販売に準じた運用)の対象となりうるため、以下の項目を用意する。

| 項目 | 内容(案) |
|---|---|
| 事業者名 | 【要記入】(個人事業主の場合は屋号+代表者氏名、法人の場合は商号) |
| 代表者 | 【要記入】 |
| 所在地 | 【要記入】(line-reservation-aiのlegal-notices-draft.md1節が整理したとおり、役務提供契約であっても通信販売の表示義務の対象に含まれうるとの一般的な傾向整理があるが、個別具体的な該非判断・開示方法は専門家確認が必要な点は変わらない) |
| 連絡先(電話番号・メールアドレス) | 【要記入】 |
| 販売価格 | pricing-plan.md(フェーズ4)のプラン表に準拠。「都度プラン480円(税込)/1回、月額フリーパス980円/月(税込)・生成回数無制限」 |
| 支払方法 | クレジットカード決済(Stripe Checkout経由。都度プランは`mode=payment`、月額フリーパスは`mode=subscription`。実アカウント開設・本番APIキー取得はオーナー承認待ち) |
| 支払時期 | 都度プラン: 生成リクエスト確定時点で即時課金。月額フリーパス: 初回申込時点から月次自動課金(無料トライアルの有無は未確定〈要検討〉) |
| 提供時期 | 決済完了後、即時にブラウザ上で結果(遠征プラン下書き・タイムテーブル草案・費用見積り・ハシゴ無理チェック)を表示 |
| 返品・キャンセルについて | 役務提供(生成結果の提供)のため物理的な返品はなし。都度プランは生成完了後の取消・返金は原則不可。月額フリーパスはいつでも次回請求サイクル分から解約可能、日割り返金は行わない旨を明記(要確定) |
| 動作環境 | Webブラウザ(LINE等の外部アプリ連携を前提としない。対応ブラウザの範囲は実装着手時に確定) |

- 「所在地の常時表示要否」「返金ポリシーの詳細」は法律専門家への確認が必要な未確定事項として
  残す(line-reservation-aiのlegal-notices-draft.md1節の一般的傾向整理を参考情報として踏襲するが、
  本venture独自の追加調査は未実施)。
- Stripeとの加盟店契約(実アカウント開設・本人確認)には、この特商法表記の整備が前提条件となる。

## 2. プライバシーポリシー(案)

### 2.1 取得する情報

- 利用者が入力する情報: 当選公演の会場・日時・枚数、予算感、現地でのグッズ購入希望、
  前後の予定等(本サービスの出力生成に必要な範囲の入力項目、venue-master.json等との照合に
  用いる会場名を含む)。
- 月額フリーパス契約時にStripe Checkoutが標準で収集する情報: メールアドレス(`monthly_pass`
  ドキュメントの`email`フィールド、monthly-pass-identity-design.mdフェーズ7参照)。
- 課金に関する情報: 決済代行サービス経由のクレジットカード情報(本サービス側では非保持、
  決済代行事業者が管理)。
- 会員登録・ログインは行わないため、氏名・パスワード等の会員情報は取得しない。月額フリーパス
  利用者の識別はメールアドレス起点で発行する`accessToken`(推測不能なランダム文字列)による
  (monthly-pass-identity-design.mdフェーズ7)。

### 2.2 利用目的

- 遠征プラン下書き・タイムテーブル草案・費用見積り・ハシゴ無理チェックの生成という、本サービス
  提供に必要な範囲での利用。
- LLM(生成AI)API(Claude API等)への問い合わせを通じた、入力内容の解釈・出力生成。
- 月額フリーパスの契約状態管理(`subscriptionStatus`の確認)、異常な生成回数の検知
  (generation-count-design.mdフェーズ8、個人の特定・追跡を目的としない集計目的に限定)。

### 2.3 第三者提供・委託

- 出力生成のため、外部のLLM APIプロバイダ(Claude API等)に入力内容を送信する。プロバイダ側の
  データ取り扱い方針(学習利用の有無等)を確認の上、委託先として明記する必要がある
  (現時点でAPIプロバイダ未契約のため詳細は今後確認)。
- 決済情報は決済代行サービス(Stripe)に直接入力・管理され、本サービス運営者はカード番号等を
  保持しない。
- 法令に基づく開示要請があった場合を除き、上記以外の第三者への提供は行わない。

### 2.4 保存期間・削除

data-retention-policy.md(本フェーズで新規作成)で整理した保存期間ポリシー(暫定値、実運用
開始後の見直しを予定)を反映する。

| データ種別 | 保存期間(目安) |
|---|---|
| 都度プランの入力・出力 | 原則保存しない(障害調査用の短期ログのみ30日) |
| 月額フリーパス契約情報(`monthly_pass`) | 契約終了から1年 |
| 生成回数ログ(`generation_log`、異常検知用) | 発生日から6か月 |

- 上記期間の経過後、原則として当該データを削除する。削除は自動実行せず、本サービス運営者が
  個別に確認したうえで行う(data-retention-policy.md3節参照)。
- 開示・削除請求への対応は、都度プラン利用者については対象データが実質的に存在しないため
  原則対応不要、月額フリーパス利用者については決済に使用したメールアドレスを手がかりに
  本人確認のうえ対応する(data-retention-policy.md4節参照)。

### 2.5 未検証・要確認事項

- LLM APIプロバイダとの契約内容(データ学習への利用有無、保存期間、国外移転の有無)は
  APIプロバイダ契約後でないと確定できないため、pending-approval.md記載の「実LLM API投入」の
  承認・契約後に本節を更新する必要がある。
- 「AIが対応していることの開示要否」は、line-reservation-aiのlegal-notices-draft.md2.5節が
  整理した一般的傾向(2026年時点で義務付ける法律は見当たらないが、ステルスマーケティング
  規制との関係で任意の開示表示が推奨される)を参考情報として踏襲するが、本venture独自の
  追加調査は未実施であり、最終判断は法律専門家への確認が必要な事項として残す。
- 月額フリーパスの無料トライアル有無(1節「支払時期」欄)は、pricing-plan.md(フェーズ4)
  時点で確定していないため、確定後に本節・1節を更新する必要がある。

## 3. LP掲載用ページ構成の設計

本venture固有の事情として、line-reservation-ai等のLINE前提6ventureと異なり、ランディング
ページ自体(landing-page-copy-draft.md相当)がoshien-pashaにはまだ作成されていない。したがって
本節はline-reservation-aiのlegal-notices-draft.md3節(フッターからのページ分割方針)のうち、
LP本体の構造に依存しない部分(見出し順・公開前チェック項目)のみを先行して整理し、ページ分割
方針(フッターリンク配置等)はLP本体の作成時に改めて検討する課題として残す。

### 3.1 特定商取引法に基づく表記ページの見出し順

1節の表の行順をそのまま見出し順とする: 事業者名 → 代表者 → 所在地 → 連絡先 → 販売価格 →
支払方法 → 支払時期 → 提供時期 → 返品・キャンセルについて → 動作環境。

### 3.2 プライバシーポリシーページの見出し順

2.1〜2.4節の節構成をそのまま見出しに対応させる: 取得する情報 → 利用目的 → 第三者提供・委託 →
保存期間・削除 → (末尾に)お問い合わせ窓口(1節の連絡先と同一)。2.5節(未検証・要確認事項)は
社内検討用のメモであり、専門家確認が完了し本文に反映された後は顧客向けページには掲載しない。

### 3.3 公開前チェック項目(将来の実装時用メモ)

- 1節の表に`【要記入】`が残っていないこと
- 2.5節(未検証・要確認事項)が解消され空になっていること、またはオーナーが未解消のまま
  掲載する判断をした場合はその旨を明記すること
- 月額フリーパスの無料トライアル有無が確定し、1節「支払時期」欄が確定記述になっていること
- LP本体(未作成)のフッターへの実際のリンク設置は、LP本体作成時に別途対応する
