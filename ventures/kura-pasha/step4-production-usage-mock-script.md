# ステップ4(本番運用時のメモ送信)のトーク画面モックスクリプト

## 位置づけ

craftsman-profile-collection-design.md「4. 残課題」が次フェーズ候補として残していた
「ステップ1(本設計に基づく収集フロー)・ステップ4(本番運用時のメモ送信)のモックスクリプト
作成」のうち、ステップ4側を本ドキュメントで対応する(ステップ1・2側は
step1-2-linking-and-profile-collection-mock-script.mdで対応済み)。aircon-pasha/
step5-production-usage-mock-script.mdと同じ位置づけで、実LINE公式アカウント・実LLM APIの
接続・画像生成は一切行っていない。

## モック対象ケース

step3-trial-generation-mock-script.mdが接続テストの例として`G1_new_basic`(新規制作)を
既に使用しているため、本番運用の多様さを示すため本ドキュメントは別のサンプルケース
`G2_repair_with_remarks`(修理、`schema/validate_test_cases.py`記載。32件中パス済み)を
素材とした。新しい事実確認・WebSearch調査は行わず、既存サンプルの出力フィールド
(`order_summary`・`delivery_notice`・`care_notice`)の内容をそのままトーク画面の文面として
再構成した。

## トーク画面の見え方(案)

```
[LINE公式アカウント「鞍パシャッと」とのトーク画面(手順3の接続テスト完了後、本番運用中)]

(代表者から送信・実際の依頼者からの修理依頼メモ)
区分: 修理、ウエスタン鞍、馬革、ステンレス金具、日常騎乗用、納期2週間、備考: 鐙革の縫い目が
ほつれている、金具のさびが目立つ

(アプリから自動返信・3つの下書きが連続して届く想定)

――――――――――――――――
【受注内容整理メモ】
区分:修理/鞍の型:ウエスタン/革の種類:馬革/金具仕様:ステンレス金具/用途:日常騎乗用/
納期:2週間/症状:鐙革の縫い目がほつれている、金具のさびが目立つ
――――――――――――――――
【納品案内 下書き】
修理箇所(鐙革の縫い目、金具のさび)の補修が完了しました。修理直後は新規制作時ほど長期の
慣らしは不要ですが、初回騎乗時は締め具合に違和感が無いかご確認ください。
――――――――――――――――
【お手入れ案内 下書き】
定期的にオイル・クリームで革に保湿を与えてください。高温多湿・直射日光を避けた場所で保管し、
カビ・ひび割れを防いでください。金具部分は使用後に乾拭きしさびを防いでください。
――――――――――――――――

この内容で問題なければ、下の2つ(納品案内・お手入れ案内)をそのまま依頼者様への送付文として
お使いいただけます。表現を直したい場合は、コピーしてから手直しのうえお使いください。

※ 依頼者以外の第三者(他の馬主様・関係者様等)の氏名・連絡先等は、メモへの記載を避けるか、
本人を特定できない表現(「所有者様」等)でご記載ください。
```

## 注記・限界

- 上記は`schema/validate_test_cases.py`の`G2_repair_with_remarks`(机上検証・スキーマ適合済み)
  の出力フィールド内容をそのまま文面化したものであり、実際にLLM APIを呼び出して生成した
  ものではない。実LLM接続後、同じ入力メモに対して実際にこの通りの文面が返るかは
  output-samples-validation.md「残る未検証事項」と同じ限界として引き続き未検証。
- 入力メモの末尾に付記した第三者情報の留意事項は、onboarding-guide.md手順4・厳守事項9
  (requester-personal-info-inclusion-handling-design.md)の案内文を踏まえたもので、本モック
  スクリプトでは実際のアプリ応答に含めず、職人向け参考情報として別枠で付記した
  (厳守事項9自体はLLM応答本文への自動挿入を想定した設計ではないため)。
- 本番運用開始(手順3の接続テスト完了)自体は実LINE公式アカウント接続(オーナー承認待ち)が
  前提のため、本スクリプトはトーク画面の見え方を事前に示す資料にとどまる。
