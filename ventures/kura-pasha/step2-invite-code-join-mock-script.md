# 複数職人プラン・招待コード参加のトーク画面モックスクリプト

## 位置づけ

step1-2-linking-and-profile-collection-mock-script.md「次のステップ候補」が次回以降の
課題として残していた「複数職人プラン(招待コードでの参加)のオンボーディング部分の
モックスクリプト化」に対応する。aircon-pasha・course-set-pasha・本venture自身の既存
モックスクリプトと同じ位置づけで、実LINE公式アカウント・実LLM APIの接続・画像生成は
一切行っていない。新しい事実確認・WebSearch調査は行わず、既存実装
(`prototype/workshop_linking.py`・`prototype/cloud_function_webhook.py`)の文言・分岐を
そのまま再構成した。

## モック対象ケース

craftsman-account-linking-design.md 5節・11節(フェーズ97・99・192)で設計・実装済みの、
複数職人プラン(`plan_id == "multi_craftsman"`)の契約者が招待コードを発行し、追加したい
職人がそのコードをLINEトークへ送信して工房に合流するまでの一連の流れを対象とする。
あわせて、対象外ケース(1人用プランでの発行試行)は全文脈の再現ではなく注記のみで
扱う(エラー発生時の案内文言のみが実装上の差分であり、トーク画面としての見え方自体は
LINKING_REQUIRED_MESSAGEと同様の単発メッセージであるため)。

- `resolve_workshop_invite_request()`・`format_workshop_invite_reply_message()`
  (`prototype/cloud_function_webhook.py`)が返す、招待コード発行時の返信文。
- `INVITE_JOIN_SUCCESS_MESSAGE`(同ファイル)が返す、招待コード解決成功時のウェルカム
  メッセージ本文。
- 招待コード「H4R2MX」は`_generate_candidate_code()`の出力形式(英数字6文字)に合わせた
  架空の例であり、実際にコード生成関数を呼び出した値ではない(連携コード
  「7K2P9Q」と同じ位置づけ、step1-2側と区別できる値を採用した)。

## 注記・限界

- 招待コードで合流した職人は、`INVITE_JOIN_SUCCESS_MESSAGE`の分岐がプロフィール収集
  3問シーケンス(`profile_collection_step`)を経由しないため(design 11節の対象外、
  INDEX.md「既知の運営課題」直前の記載参照)、工房名・連絡先メール・利用形態の追加質問は
  発生しない。これは契約者が工房作成時に既にこれらの情報を回答済みであり、追加職人は
  同じ工房に合流するだけという設計上の判断であって実装漏れではない。
- 本モックスクリプトでは、招待コード自体の職人への伝達(契約者→新規職人)をLINEの
  トーク機能外(対面・電話・別メモ等)の操作として扱った。本サービスが契約者の代わりに
  招待コードを第三者へ直接送信する機能(例: 電話番号入力による直接送信)は設計・実装
  いずれにも存在せず、本フェーズで新たに設計したものでもない。
- 対象外ケース(1人用プラン〈`"light"`/`"standard"`等、`multi_craftsman`以外〉の契約者が
  「職人を追加したい」と送信した場合)は、`UPGRADE_REQUIRED_FOR_INVITE_NOTICE`
  (「職人の追加には複数職人プランへの変更が必要です。プラン変更をご希望の場合はその旨
  メッセージでお知らせください。」)が単発で返信されるのみであり、トーク画面としての
  見え方に新規性がないため全文脈の再現は行わなかった。同様に人数上限(`MAX_MEMBER_COUNT`
  =5名)到達時の`INVITE_ISSUANCE_MEMBER_LIMIT_REACHED_NOTICE`・招待コード解決時の
  `MEMBER_LIMIT_REACHED_MESSAGE`も単発の案内文言であり、既に設計・実装済みのため同様に
  全文脈の再現は対象外とした。
- 契約者以外(非契約者のメンバー)が「職人を追加したい」と送信した場合の
  `CONTRACTOR_ONLY_INVITE_NOTICE`も同様の理由で対象外とした。
