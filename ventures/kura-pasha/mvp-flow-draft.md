# MVP入出力フォーマット草案

market-research.mdの示唆(修理・新規制作の両方に対応する必要がある)を踏まえ、
根来塗パシャッと・鞍パシャッと(ideas.md原案)の入出力構成を土台に、区分を追加した
草案を以下に示す。

## 入力(職人が送るメモ、例)

```
区分: 新規制作 / 修理
鞍の型: ブリティッシュ / ウエスタン / その他
革の種類: 牛革 / 馬革 / その他
金具仕様: (任意、例: ステンレス金具、真鍮金具等)
用途: 競技用 / 日常騎乗用
納期: (例: 3ヶ月、または「修理は2週間」等)
備考: (任意、修理の場合は破損箇所・症状等を記入)
```

- 「区分」は必須項目とし、修理の場合は「破損箇所・症状」を備考欄に記入してもらう
  想定(market-research.mdで確認した託革・金具交換等の修理需要に対応するため)。
- ideas.md原案の入力例(「ブリティッシュ鞍、牛革、競技用、納期3ヶ月」)は本フォーマットの
  「新規制作」区分に相当する。

## 出力

1. **受注内容整理メモ**: 上記入力項目を整理した形式(担当職人自身の備忘・作業記録用)。
2. **納品案内下書き**:
   - 新規制作の場合: 装着時の皮革のなじませ方、初期の締め具合調整の必要性、
     雨天時の取り扱い注意。
   - 修理の場合: 修理箇所の説明、修理直後の強度・馴染みに関する注意(新規制作時ほど
     長期の慣らしは不要な場合が多い旨)。
3. **お手入れ案内下書き**: オイル・クリームでの定期的な革の保湿、カビ・ひび割れ防止の
   ための保管環境、金具のさび防止手入れ(新規制作・修理共通)。

## 実際の制作作業との境界(厳守事項の方向性)

- 採寸・型紙作成・革選定・縫製・仕上げ等の専門的な制作作業・判断はAIが行わない
  (職人本人が行う前提)。
- 修理の場合の「修理可否の判断」自体(破損の程度から修理で対応できるか新規制作が
  必要かの判断)も専門的判断であり、AIは行わない。備考欄の症状はそのまま整理メモに
  転記するにとどめ、AIが独自に診断・助言を加えない設計とする(course-set-pashaの
  厳守事項1「安全確認・グレーディングへの不介入」と同種の設計方針)。

## 残課題

- llm-system-prompt-draft.mdへの落とし込み(厳守事項の明文化)。
- 出力の構造化(JSON)フォーマット設計(schema/output.schema.json相当)。
- 「区分」ごとに出力2(納品案内)の分岐が必要なため、既存の他venture(根来塗パシャッと等)
  より分岐ロジックがやや複雑になる点に留意して設計する。
