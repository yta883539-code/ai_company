# ランディングページ(LP)ワイヤーフレーム

landing-page-copy-draft.md(フェーズ76)の「次のステップ候補」(1)で挙げていたワイヤーフレーム
(セクション配置・画像イメージ)を作成する。他venture(aircon-pasha・course-set-pasha・
kura-pasha・line-reservation-ai・forklift-pasha)には既に存在するが本ventureには無かった
cross-venture parityのギャップに対応するもの。他venture同様、実装(HTML/CSS)は行わずテキスト
ベースのワイヤーフレームに留める。LP実装(landing-page/index.html)・公開自体は引き続き別の
課題(次のステップ候補(2)(3))とする。

## 設計方針

- 想定読み手(専任の警備計画・安全管理担当者を置かない個人〜小規模のライブハウス運営者・
  屋内音楽イベント主催者)は、開催準備の合間・終演後の事務作業の時間帯にスマートフォンで
  閲覧する比率が高いと想定し、他venture同様モバイル1カラムを基本レイアウトとする。
- landing-page-copy-draft.mdのセクション順(ヒーロー→課題提起→機能紹介→差別化→
  料金・トライアル→FAQ)をそのまま画面の縦の並びとする。
- 画像方針は「メモ入力→整形済み文書」というビフォーアフター訴求という点で他ventureと
  同系統を踏襲しつつ、本venture固有の2点を画像・視覚要素で明示する:
  (1)`outdoor_queue`(待機列が屋外・公道に及ぶ可能性)に応じた道路使用許可確認の注記を、
  機能紹介セクションの該当項目に警告色のバッジで目立たせる(断定的な表現を避けつつも
  「見落とされない」ことを優先する、landing-page-copy-draft.md該当箇所の方針を視覚化)。
  (2)5入力要素(`capacity`・`entry_exit_points`・`admission_type`・`staffing`・
  `outdoor_queue`)→4出力(セルフチェックリスト/警備員重点配置案・誘導アナウンス文案/
  来場者向け掲示文案/ヒヤリハット記録フォーマット例)という対応関係を、他venture
  (1入力カテゴリ→1〜2出力が多い)より入出力数が多いため、ビフォーアフター画像内で
  矢印の分岐(1つのメモ→4種類の出力カード)として見せる。
- 警備業法・興行場法・道路使用許可のいずれも代行判断の対象でないという厳守事項
  (mvp-flow-draft.md「範囲外」節)は、機能紹介セクション直後の注記とFAQの両方で
  一貫させ、ワイヤーフレーム上もその配置を明示する。

## 画像・ビジュアル方針まとめ

| セクション | 画像案 | 備考 |
|---|---|---|
| ヒーロー | メモ1件→4種の出力カードへの分岐(矢印4分岐) | 最優先で作る画像。本venture固有の「1入力→4出力」構成を1画面で伝える(他venture1出力中心との違い) |
| 課題提起 | 画像なし(テキスト+チェックアイコンのみ) | 共感重視、視覚要素は最小限(他venture同様) |
| 解決策・機能紹介 | 6項目に対応する番号アイコン、③に警告バッジ、⑥のみ区別枠 | 道路使用許可の注記を「見落とされない」ように警告色で強調。⑥は「やらないこと」の明示を視覚的にも区別 |
| 差別化 | 画像なし | テキスト訴求のみで十分と判断(他venture同様) |
| 料金・トライアル | 画像なし | 数字とチェックリストで訴求(3プラン併記のため他ventureよりやや縦に長くなる想定) |
| FAQ | 画像なし | アコーディオン形式、他venture同様 |
