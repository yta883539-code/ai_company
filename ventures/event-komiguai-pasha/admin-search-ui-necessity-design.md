# オーナー向け検索UIの要否検討(フェーズ57)

draft-id-last4-collision-design.md(フェーズ53)4節で確定した「(1)末尾4文字で
`one_time_draft`を絞り込み→(2)複数件ヒット時は`customer_email`と一致するものを採用」
という二段階照合を、オーナーが実際にどの画面・手段で行うかを本フェーズで検討する
(README.mdフェーズ56「次回候補(4)」)。

## 1. 検討の前提

- tech-stack.md(フェーズ7)の基本方針: 本ventureは低頻度利用(一桁〜十数件/日程度)の
  単発決済型であり、常時稼働コンポーネントを増やさない。inquiry-handling-design.md
  (フェーズ15)も同方針により、問い合わせ対応用の専用チャットボット等は新設せず
  Webフォーム+Firestore蓄積のみとしている。
- 本フェーズで問う「検索UI」は、オーナー(人間)が問い合わせ対応時に`one_time_draft`
  コレクションを検索するための画面であり、主催者向けの機能ではない。

## 2. 専用検索UIを新規開発しない方針を確定

- 低頻度運用(想定十数件/日以下)かつオーナー自身が一人で対応する前提のため、専用の
  管理画面(認証・権限管理・UIフレームワークを要する)を新設するコストは、
  tech-stack.mdの「低頻度利用に常時稼働コンポーネントを増やさない」方針に反すると
  判断した。
- 代わりに、GCPコンソールのFirestoreデータビューア(標準機能、追加実装不要)を
  オーナーの検索手段として採用する。これはGCPプロジェクトが既に存在する前提
  (one-time-checkout-no-account-design.md等)で追加費用・追加実装なしに使える。

## 3. Firestoreコンソールでの検索を成立させるためのフィールド追加

- Firestoreコンソールの標準フィルタ機能は等価(`==`)・範囲比較が中心であり、
  ドキュメントID(`draft_id`、UUID4文字列)に対する「末尾4文字一致」という部分
  一致検索は等価フィルタでは実行できない。
- このため、`one_time_draft/{draft_id}`ドキュメントに検索専用フィールド
  `draft_id_last4`(UUID4文字列の末尾4文字をそのまま複製した文字列値)を新設し、
  コンソールの等価フィルタ(`draft_id_last4 == "xxxx"`)で絞り込めるようにする。
  複合索引の追加作成は不要(単一フィールドの等価フィルタはFirestoreの自動索引で
  足りる)。
- 複数件ヒットした場合の2段階目(`customer_email`一致確認)も、同じFirestore
  コンソールのフィルタに`customer_email`の等価条件を追加するか、ヒットした数件
  (想定数件程度)を目視で見比べるだけで足りる規模と判断した。

## 4. 書き込みタイミング

- `draft_id_last4`はStripe Webhook受信時に`draft_id`(UUID4)を生成するのと同じ
  タイミングで、文字列操作(末尾4文字の切り出し)のみで導出・保存する。追加の
  外部呼び出し・追加の入力は発生しない。
- one-time-checkout-no-account-design.md(フェーズ10)・draft-id-last4-collision-
  design.md(フェーズ53)に記載の`one_time_draft`ドキュメント構造に、本フィールドを
  追加する旨を追記する(5節参照)。

## 5. 更新箇所

- draft-id-last4-collision-design.md 4節: オーナー側の検索手順を「GCPコンソールの
  Firestoreデータビューアで`draft_id_last4`フィールドを等価フィルタして絞り込み、
  複数件ヒット時は`customer_email`で絞り込む」という具体的な操作手順として確定する
  旨、本ファイル参照の形で反映(本節末尾の追記として記録)。
- one-time-checkout-no-account-design.mdの`one_time_draft`ドキュメント構造に
  `draft_id_last4`フィールドを追加する。

## 6. 規模が拡大した場合の再検討条件

- 将来、同時期に未失効の`one_time_draft`が常時数十〜百件規模に達し、GCPコンソールの
  目視絞り込みでは対応時間が無視できなくなった場合は、専用の軽量検索ツール(社内限定
  の簡易フォーム等)の新設を再検討する。現時点ではその規模に達する見込みがないため、
  本フェーズでは「専用検索UIは不要、GCPコンソール+`draft_id_last4`フィールドで足りる」
  と結論する。
