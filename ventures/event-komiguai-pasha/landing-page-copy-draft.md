# サービス紹介ランディングページ(LP)コピー草案(フェーズ76)

market-research.md(消費者安全調査委員会の経過報告・規制整理)・mvp-flow-draft.md(5入力
要素・4出力)・pricing-plan.md(開催件数ベースの3プラン・無料トライアル条件)・
legal-notices-draft.md(フェーズ75)を踏まえ、想定顧客(専任の警備計画・安全管理担当者を
置かない個人〜小規模のライブハウス運営者・屋内音楽イベント主催者)向けに、サービス自体を
紹介するLPのコピー草案を初めて作成する。他venture(aircon-pasha・course-set-pasha・
forklift-pasha・kura-pasha・line-reservation-ai)はいずれもlanding-page-copy-draft.md・
landing-page-wireframe.md・landing-page/index.html(非公開の試作HTML)を作成済みだが、
本ventureにはこれらが一つも存在していなかったcross-venture parityギャップであることを
確認した(フェーズ75の次回候補(2)に対応)。実際のLP実装・公開は行わず、文言の草案のみ
(本文書の作成自体は「公開」に該当しない)。

## 想定する読み手

- 専任の警備計画・安全管理担当者を置かない個人経営の小規模ライブハウス運営者(自主企画・
  貸しライブハウスとしての主催者側入力の両方を想定)。
- 単発の屋内トークイベント・ポップアップ公演の主催者(月1〜2件程度、またはイベント単位の
  都度利用)。
- market-research.mdで確認した消費者安全調査委員会の経過報告(2026年9月30日公表)の
  問題意識(入退場時の混雑を「気になった」来場者が約4割、「さらなる対応や工夫の必要性を
  感じた」主催者が79.2%)を踏まえ、同種の不安を抱える層を主な読み手と想定する。

## ファーストビュー(ヒーローセクション)

```
見出し: 会場キャパと入退場口数、そのメモだけで大丈夫ですか?
サブ見出し: 混雑確認チェックリストも、警備員配置案も、AIが下書きします。
CTAボタン: 30日間無料で試してみる(カード登録不要)
```
- 他venture(aircon-pasha・kura-pasha等)が「依頼者への説明づくり」「受注時の聞き取り整理」
  を主語にしていたのに対し、本ventureは「入退場時の混雑確認」という安全管理上の不安そのものを
  ヒーローセクションの主語に置く。これは市場調査の根拠事実(消費者安全調査委員会の経過報告)
  に最も近い論点をファーストビューで提示し、読み手に直接関係する課題であることを即座に
  伝える狙い。
- 警備計画の最終確定・入場制限の実施判断は主催者自身が行うという厳守事項(mvp-flow-draft.md
  「範囲外」節)をヒーローセクションでも損なわないよう、「下書きします」という語を用い、
  「警備計画を作ります」「安全を保証します」等の断定的な表現は避ける。
- CTA直下の「カード登録不要」はpricing-plan.mdの無料トライアル条件(初回生成から30日間、
  または生成3回到達のいずれか早い方)をそのまま反映。期間は他venture(course-set-pasha等の
  14日間)より長い「30日間」とし、pricing-plan.mdで「本venture想定顧客の開催頻度が月数件
  程度と少なく、30日以内に3回到達する前にトライアル期間自体が終了するケースが多い」と
  整理した設計をそのままLPに表現した。

## 課題提起セクション

```
見出し: こんなことに、不安を感じていませんか?
- 会場キャパ・入場口数に対して、開場直後の入場が集中しないか毎回自分の経験と感覚だけで
  判断している
- 警備員の人数は確保できているが、どの時間帯・どのエリアに重点配置すべきかの根拠を
  持てていない
- 入場待機列が屋外・公道に及ぶ可能性があるかどうか、道路使用許可の要否を確認し忘れそうで
  不安
- ヒヤリハット(将棋倒しの未然事例等)が起きても、記録のフォーマットが決まっておらず
  その場の対応で終わってしまう
```
- market-research.mdの消費者安全調査委員会の経過報告(入退場時の混雑に「気になった」来場者
  約4割、「さらなる対応や工夫の必要性を感じた」主催者79.2%)と、mvp-flow-draft.mdの5入力
  要素(`capacity`・`entry_exit_points`・`admission_type`・`staffing`・`outdoor_queue`)を
  一人称の悩みに変換した。3項目目(`outdoor_queue`)・4項目目(ヒヤリハット記録)は
  それぞれ出力3・出力4への伏線とする。

## 解決策・機能紹介セクション

```
見出し: 「イベントこみぐあいパシャっと」がやること
1. 会場キャパ・入場口数・入場方式・警備人数・待機列が屋外に及ぶ可能性をメモで送るだけ
2. 入退場時混雑確認セルフチェックリストを自動生成します
   (消費者安全調査委員会の経過報告が指摘する確認項目〈入退場口数がキャパに対し十分か、
   導線上に合流・ボトルネックが生じないか等〉に基づく下書きです)
3. 警備員重点配置案・分散入場誘導アナウンス文案を自動生成します
4. 来場者向け整列・分散入場案内の掲示文案を自動生成します
   (待機列が屋外・公道に及ぶ可能性がある場合は、道路使用許可の要否確認を促す注記を
   必ず付けます)
5. ヒヤリハット記録フォーマット例も、あわせて自動生成します
```
- mvp-flow-draft.mdの4出力(セルフチェックリスト・警備員重点配置案/誘導アナウンス文案・
  来場者向け掲示文案・ヒヤリハット記録フォーマット例)をそのまま機能紹介の項番に対応させた。
  `outdoor_queue`に応じた道路使用許可の注記(mvp-flow-draft.md「入力」節)は、本venture固有の
  安全上重要な注記であるため機能紹介内で明示し、読み手に「見落とされない」という安心感を
  与える狙い。
- 警備業法・興行場法・道路使用許可のいずれも本サービスが代行判断する対象ではないこと
  (market-research.mdフェーズ1「規制・法令面の確認」、mvp-flow-draft.md「範囲外」節)は、
  機能紹介セクションの直後に小さな注記文として置く方針とする(FAQセクションでも再掲)。

## 差別化セクション

```
見出し: 警備会社向けの大規模システムではありません
- 有人警備計画・シフト管理SaaSは警備会社・大規模イベント主催者向けの業務システムで、
  専任の安全担当者がいない小規模ライブハウス・屋内イベント主催者には価格・機能の両面で

  野外イベント向けの高額なシステムです
- 「イベントこみぐあいパシャっと」は、チャット/フォームへの簡単なメモ入力だけで一次案を
  下書きする、数百〜数千人規模の屋内イベント主催者のための低価格なセルフチェックツールです
```
- market-research.mdフェーズ1・3の競合調査結果(有人警備計画・シフト管理SaaSは価格帯・
  用途が合わない、AI大規模イベント動線予測プラットフォームは対象規模・手法が異なり競合
  しない)をそのまま差別化の根拠として転用した。

## FAQセクション(案)

```
Q. 警備計画はこのサービスだけで完成しますか?
A. いいえ。生成されるのはあくまで一次案(下書き)です。警備計画の最終確定・入場制限の
   実施判断は、主催者様・警備責任者様ご自身で行ってください。

Q. 外部の警備会社への発注や、警察署への届出も代わりにやってもらえますか?
A. いいえ。外部警備会社への発注契約、所轄警察署への道路使用許可申請・届出代行は行いません。
   入場待機列が屋外・公道に及ぶ可能性がある場合は、その旨の確認を促す注記を出力に付けますが、
   実際の申請はご自身で行っていただく必要があります。

Q. 入力した会場キャパシティの数値が合っているか確認してもらえますか?
A. いいえ。入力いただいた数値をそのまま一次案の生成に用います。消防法上の定員・座席表上の
   数値等、複数の数値の正しさの確認はご自身の責任で行ってください(複数の数値を併記して
   入力いただいた場合は、どの数値を基準に使ったかを出力内に明示します)。

Q. 単発利用とサブスクプラン、どちらを選べばいいですか?
A. 年数回程度しか屋内イベントを主催されない場合は単発利用(500円/回)、月に複数件開催
   される場合はライト/スタンダードプランがお得です。まずは無料トライアルでお試しください。
```
- mvp-flow-draft.md「範囲外」節(警備計画の最終確定・入場制限の実施判断への不介入、外部
  警備会社への発注代行・届出代行の対象外)、capacityの定義方針(フェーズ42、複数の収容人数が
  併記される場合の扱い)を、読み手が誤解しやすい点としてFAQに明示した。他venture同様、
  「断定しない」という厳守事項をLPのFAQでも一貫させる狙い。
