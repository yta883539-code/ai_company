# 保留タイムアウトのユーザー体験(待機メッセージ文言設計)

double-booking-prevention.md で設計した「仮押さえ(pending)→確定」の2段階方式のうち、
仮押さえ中に顧客へどう伝えるか、タイムアウトが発生した場合にどう案内するかの会話文言を設計する。

## 前提
- 仮押さえのタイムアウトは5分(double-booking-prevention.md の仮設定)。
- 仮押さえ中に必要なのは主に「氏名確認」で、通常は数十秒〜1分程度で完了する見込み。
- 5分間丸ごと顧客を待たせるのではなく、氏名確認の返信が来ない場合の「催促」を挟んでから解放する2段階運用にする。

## 会話文言案

### 1. 仮押さえ直後(氏名確認を依頼する時点)
```
AI: 8/9(土) 15:30〜 カットで仮押さえいたしました。
    お名前を教えていただけますか?(5分以内にご返信いただけますと確実にご予約いただけます)
```
- 「仮押さえ」という言葉を明示し、確定ではないことを顧客に伝える(誤解によるトラブル防止)。
- タイムアウトの目安(5分)を先に伝えることで、返信を促す。

### 2. 一定時間(例: 3分)返信がない場合の催促メッセージ
```
AI: 先ほどの8/9(土) 15:30〜のご予約枠、あと少しで保留時間が終了します。
    お名前だけで結構ですので、よろしければご返信ください!
```
- 残り時間を厳密な秒数では出さず「あと少しで」という柔らかい表現にする(過度な焦らせ感を避ける)。
- 催促は1回のみとし、しつこい印象を与えない。

### 3. タイムアウトで枠を解放した場合
```
AI: すみません、5分以内にご返信いただけなかったため、8/9(土) 15:30〜の仮押さえを解除いたしました。
    まだご希望でしたら、あらためて空き状況をご案内しますので教えてください!
```
- 顧客側の落ち度を強調しすぎない(「すみません」から始め、店側からのお詫び口調にする)。
- 再度の空き確認へ自然に誘導し、離脱を防ぐ。

### 4. 保留取得に失敗した場合(他の顧客が先に確定・仮押さえ済み)
```
AI: 大変申し訳ございません、ちょうどそちらの枠が埋まってしまいました。
    近い時間ですと 8/9(土) 17:00 / 8/10(日) 14:00 が空いております。いかがでしょうか?
```
- double-booking-prevention.md の「競合時のリカバリー」で定義済みの挙動に、実際の文言を当てた。

## 設計メモ
- 「仮押さえ」「保留」という業界寄りの言葉を顧客向け文言でも維持するか迷ったが、
  誤解防止(確定と誤認させない)を優先し、あえて平易な言い換えはせず明示することにした。
- 催促メッセージのタイミング(3分時点)は暫定値。実運用データが取れたら、
  氏名確認にかかる実際の平均時間を見て調整する。

## 未検証の仮説(要検証)
- 「あと少しで」のような曖昧な残り時間表現が、顧客にとって不安・不親切に感じられないか
- 催促を1回に絞る運用で、タイムアウトによる機会損失(枠が解放されて他の顧客に取られる)がどの程度発生するか
