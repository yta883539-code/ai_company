# ランディングページ(LP)ワイヤーフレーム

landing-page-copy-draft.mdの「次のステップ候補」で挙げていた、LPコピーに対応する
ワイヤーフレーム(セクション配置・画像イメージ)を作成する。owner-settings-wireframe.mdと
同様、実装(HTML/CSS)は行わずテキストベースのワイヤーフレームに留める。LP実装・公開自体は
「公開」に該当するため引き続きオーナー承認後の課題とする。

## 設計方針

- 想定読み手(美容室・整体院・パーソナルジム・個人講師業のオーナー)はスマートフォンで
  閲覧する比率が高いと想定し、モバイル1カラムを基本レイアウトとする。PC幅では中央寄せの
  1カラムのまま最大幅を制限する程度に留め、複雑な多カラムレイアウトは組まない
  (owner-settings-wireframe.mdの「多機能な管理画面は作らない」方針をLPにも踏襲)。
- landing-page-copy-draft.mdのセクション順(ヒーロー→課題提起→解決策→「いつものLINEのまま」→
  料金・トライアル→FAQ)をそのまま画面の縦の並びとする。同ファイルの「未検証の仮説」に
  ある通り、体験差別化と価格訴求の順序はABテスト対象の仮説であり、本ワイヤーフレームでは
  現状のコピー草案の順序を暫定案として採用する。
- 各セクションの画像は「LINEのトーク画面のスクリーンショット風モックアップ」を軸に統一する。
  抽象的なイラスト素材より、実際の会話体験(candidate-presentation-and-selection-design.mdの
  候補提示文言、tone-and-manner-guideline.mdの確定メッセージ)がそのまま伝わる方が、
  「新しいアプリはいらない」という差別化ポイントの説得力が増すと判断した。
  画像制作(実際のスクリーンショット合成・デザイン)自体は今回のスコープ外とし、
  各セクションに「どのトーク内容を見せるか」の指定のみ行う。

## 画像・ビジュアル方針まとめ

| セクション | 画像案 | 備考 |
|---|---|---|
| ヒーロー | LINEトーク画面モックアップ(候補提示→確定の3コマ) | 最優先で作る画像。差別化ポイントの核心 |
| 課題提起 | 画像なし(テキスト+チェックアイコンのみ) | 共感重視、視覚要素は最小限に |
| 解決策・機能紹介 | 5項目に対応する簡易アイコン(番号のみでも可) | 凝ったイラストより機能の見分けやすさ優先 |
| 「いつものLINEのまま」 | トーク画面モックアップ(店舗アイコン付き、シンプル版・対比構成なし) | ヒーローは「候補提示→確定」の3コマでAIの機能を見せる、本セクションは店舗アイコン・トーク履歴込みの1枚で「見慣れた画面そのもの」を見せる、と役割を分担したため重複しない |
| 料金・トライアル | 画像なし | 数字とチェックリストで訴求 |
| FAQ | 画像なし | アコーディオンUIのみ |

CTAボタンは「14日間無料で試してみる」の文言・配置(ヒーロー/料金セクション/フッター前の計3箇所)で
統一し、tone-and-manner-guideline.mdの「1メッセージ1用件」の考え方を踏襲して1画面に複数の
異なる訴求を詰め込みすぎない構成とした。

## 未確定・今後の課題

- LINEトーク画面モックアップ画像そのものの制作(実際のスクリーンショット合成またはデザイン
  ツールでの作成)は本ワイヤーフレームのスコープ外。制作着手時にどのツール・素材を使うかは
  未検討(Canva等の外部デザインツール利用も選択肢だが、アカウント連携が発生する場合は
  範囲を要確認)。
- (解消済み 2026-08-06 23:00 UTC: 「いつものLINEのまま」セクションの対比構成(予約専用アプリ画面との
  並置)は不採用と決定。理由は(1)対比構成は画像制作工数が増えるうえ、比較対象となる「予約専用
  アプリ」自体を本サービスは持たない(差別化ポイントが「アプリを作らないこと」なので、存在しない
  アプリ画面をわざわざ作って見せるのは訴求として本末転倒)、(2)ヒーロー画像で既に「候補提示→確定」の
  3コマによりAIとのやり取りは見せているため、本セクションでは店舗アイコン・トーク履歴を含む画面全体を
  1枚見せて「これが普段使っているLINEそのもの」という安心感を伝える役割に絞る方が両セクションの
  重複を避けられる。上記「画像・ビジュアル方針まとめ」表・画面構成図に反映済み)
- 実際のHTML/CSS実装、ドメイン取得、ホスティングはいずれも「公開」に該当するため未着手。
  着手にはオーナー承認が必要(pending-approval.md参照)。
- customer-interview-design.mdのヒアリング結果が得られた場合、課題提起セクションの4項目の
  優先順位・アイコンの見せ方を実際の声で見直す(landing-page-copy-draft.mdの既存の申し送り事項)。
