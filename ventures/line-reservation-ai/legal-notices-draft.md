## 1. 特定商取引法に基づく表記(案)

本サービスは月額課金のSaaS(役務提供)であり、通信販売の「商品」の売買ではないが、
継続的な役務提供契約として特定商取引法の表示義務(通信販売に準じた運用)の対象と
なりうるため、以下の項目を用意する。

| 項目 | 内容(案) |
|---|---|
| 事業者名 | 【要記入】(個人事業主の場合は屋号+代表者氏名、法人の場合は商号) |
| 代表者 | 【要記入】 |
| 所在地 | 【要記入】(個人事業主が自宅住所の開示を望まない場合、開示請求があった際に遅滞なく開示する旨を明記する運用も可。ただし2022年施行の特商法改正でネット通販事業者は原則所在地の常時表示が必要とされており、サブスク型役務提供への適用範囲は要専門家確認。2026-08-02のweb調査では、消費者庁「特定商取引法ガイド」上、有償の情報配信サービス等「役務提供契約」に基づくものも通信販売の表示義務の対象に含まれるとされており、本サービス(月額課金のLINE予約代行SaaS)も同様に対象となる可能性が高いと考えられる。ただし個別具体的な該非判断・開示方法(自宅住所を避ける代替手段の可否含む)は専門家確認が必要な点は変わらない) |
| 連絡先(電話番号・メールアドレス) | 【要記入】 |
| 販売価格 | pricing-plan.mdのプラン表に準拠。「月額2,980円〜(税込)、プラン詳細は申込フロー内で提示」 |
| 支払方法 | クレジットカード決済(決済代行サービス経由、deposit-payment-research.md記載のPAY.JP/Stripe等を想定) |
| 支払時期 | 無料トライアル終了後、契約プラン確定時点から月次自動課金 |
| 提供時期 | 申込完了後、LINE公式アカウント連携完了次第、即時利用開始 |
| 返品・キャンセルについて | 役務提供(SaaS利用)のため物理的な返品はなし。契約者はいつでも次回請求サイクル分から解約可能。日割り返金は行わない旨を明記(要確定) |
| 動作環境 | LINEアプリ(公式アカウント運用のため店舗側はLINE公式アカウントの開設が必要) |

- 「所在地の常時表示要否」「返金ポリシーの詳細」は法律専門家への確認が必要な未確定事項として残す(2026-08-02時点のweb調査結果は上表「所在地」欄に反映。特定商取引法自体は2026年1月設置予定の消費者庁「デジタル取引・景品表示法検討委員会」で見直しが検討されており、2026年夏頃に中間とりまとめ、正式な法改正は早くとも2027年以降の見込みで、現時点(2026-08-02)では現行法の解釈が前提となる点に留意)。
- 決済代行サービスとの加盟店契約(deposit-payment-research.md既出)には、この特商法表記の整備が前提条件となる。

## 2. プライバシーポリシー(案)

### 2.1 取得する情報

- LINE公式アカウント連携により取得される情報: 店舗の顧客(エンドユーザー)のLINEユーザーID、
  トーク履歴の中で予約に関連するやり取り(氏名・希望日時・メニュー等、顧客が入力した内容)
- 店舗オーナーが設定画面で登録する情報: 店舗名・営業時間・メニュー・料金・FAQ情報(住所・駐車場等)
- 課金に関する情報: 決済代行サービス経由のクレジットカード情報(本サービス側では非保持、決済代行事業者が管理)

### 2.2 利用目的

- 予約の空き時間確認・確定・前日リマインド等、本サービスの提供に必要な範囲での利用
- LLM(生成AI)API(Claude API等)への問い合わせを通じた、顧客とのやり取りの解釈・返信文生成
- サービス改善のための統計的な利用状況分析(個人を特定しない形での集計に限定する方針)

### 2.3 第三者提供・委託

- 会話内容の解釈・返信文生成のため、外部のLLM APIプロバイダ(Claude API等)に会話内容を送信する。
  プロバイダ側のデータ取り扱い方針(学習利用の有無等)を確認の上、利用規約・プライバシーポリシーに
  委託先として明記する必要がある(現時点でAPIプロバイダ未契約のため詳細は今後確認)。
- 決済情報は決済代行サービスに直接入力・管理され、本サービス運営者はカード番号等を保持しない。
- 法令に基づく開示要請があった場合を除き、上記以外の第三者への提供は行わない。

### 2.4 保存期間・削除

data-retention-policy.md(2026-08-01新規作成、2026-08-14に店舗レコードの節を追加)で
整理した保存期間ポリシー(暫定値、実運用開始後の見直しを予定)を反映する。

| データ種別 | 保存期間(目安) |
|---|---|
| 予約実績(確定済みの予約) | 確定日から3年 |
| 会話履歴(アーカイブ済み) | アーカイブ日(`archivedAt`)から1年 |
| 通知ログ(エスカレーション・FAQ未解決等の記録) | 発生日から6か月 |
| 店舗レコード(オーナー向け設定・課金状態) | 休止モード4通目の再通知(移行から90日後)からさらに1年、
無反応・無操作が続いた場合に削除候補として洗い出す |

- 上記期間の経過後、原則として当該データを削除する。削除バッチジョブの具体的な実装は、
  ホスティング基盤確定・オーナー承認後の実装フェーズの課題として残る(MVP初期の
  スプレッドシート運用段階では手動削除で代替)。
- 店舗レコードの削除候補洗い出し後は、削除前にオーナーへ最終確認を行う(休止モードで
  既にLINEチャネルがブロックされている場合の代替通知手段は今後の課題)。
- 店舗オーナー・エンドユーザーからの開示・削除請求への対応窓口は、1節の連絡先
  【要記入】と同一とする。エンドユーザー(顧客)からの請求は、店舗オーナー経由で
  受け付ける想定(本サービス運営者への直接請求ではなく、まず店舗オーナーに連絡する
  導線を案内する)。
- 上記の期間は暫定値であり、法的な上限を定めるものではなく、実運用開始後の実績を
  踏まえて見直す(data-retention-policy.md「今後の課題」参照)。

### 2.5 未検証・要確認事項

- LLM APIプロバイダとの契約内容(データ学習への利用有無、保存期間、国外移転の有無)は
  APIプロバイダ契約後でないと確定できないため、pending-approval.md記載の
  「実LLM API投入」の承認・契約後に本節を更新する必要がある。
- landing-page-copy-draft.mdのFAQ「AIが対応していることの開示要否」は、
  景品表示法(優良誤認表示等)の観点での要否を法律専門家に確認する必要があり、
  本ドキュメントの範囲では結論を出さない(引き続き未検証事項として保留)。
  2026-08-02のweb調査では、2026年時点の日本法上「AI生成コンテンツ・AI対応であることの開示」を
  一般的に義務付ける法律は見当たらず、広告・PR目的のコンテンツについてはステルスマーケティング規制
  (2023年10月施行)との関係で任意の開示表示が推奨される、という整理が複数の解説記事で見られた。
  本サービスの利用者(エンドユーザー)向けLINEでのAI対応自体は広告表示そのものではないため、
  ステマ規制の直接適用対象かは別途整理が必要。なお、EU AI法第50条はAI生成コンテンツの
  機械可読な検出可能化等を求め2026年8月2日から本格適用予定とされているが、本サービスはEU域内の
  利用者を対象としない前提のため直接の適用対象ではないと考えられる(EU域内展開を検討する場合は
  改めて要確認)。以上はいずれもweb調査による一般的な傾向整理であり法的助言ではないため、
  最終的な要否判断は引き続き法律専門家への確認が必要な事項として残す。
