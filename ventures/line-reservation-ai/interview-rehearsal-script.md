# ヒアリングリハーサル用台本(2026-07-30時点)

customer-interview-design.md の「未検証の仮説」で挙げた
「16問(A〜D基本12問+E任意4問)が15分に収まるか」を実施前に検証するため、
オーナー自身または社内での自己リハーサル用に読み上げ台本と時間配分の目安をまとめる。
※本ドキュメントは台本の設計のみ。実在の顧客へのヒアリング実施そのものは
pending-approval.md記載のとおりオーナー許可が必要なアクションであり、ここでは実行しない。

## 想定タイムテーブル(基本セット A〜D、目標12分)

| パート | 想定時間 | 内容 |
|---|---|---|
| オープニング | 1分 | 自己紹介・ヒアリング趣旨説明・所要時間案内 |
| A. 現状把握(Q1〜4) | 3分 | 各質問30〜45秒の回答を想定 |
| B. 価格感覚(Q5〜7) | 3分 | Q5は回答に迷いやすいため40秒程度余裕を見る |
| C. 体験・UX(Q8〜10) | 3分 | Q8は不安要素の深掘りで長引きやすい想定 |
| D. 導入障壁(Q11〜12) | 1.5分 | 短めの想定、回答が単純化しやすい |
| クロージング | 0.5分 | お礼・先行招待案内・任意設問(E)への移行確認 |
| **小計** | **12分** | |

E.(デポジット関連、Q13〜16)は「時間に余裕がある場合のみ」の任意設問のため、
基本セット12分終了後、残り3分の範囲で実施できるかを都度判断する運用とする。

## オープニング読み上げ台本(案)

> 本日はお時間をいただきありがとうございます。私たちはLINEで予約対応を自動化するAIツールを準備しておりまして、実際に現場で使っていただけそうか、率直なご意見を伺いたく本日お時間をいただきました。
> 質問は全部で12問、15分ほどを予定しています。答えにくい質問は遠慮なく「回答なし」で構いません。よろしくお願いいたします。

## 質問ごとの補足ト書き(聞き手向け)

- Q1〜4(現状把握): 数値(件数・時間)は「だいたいで大丈夫です」と前置きし、正確さより体感値を優先して聞き取る。
- Q5(価格感覚): 金額を言いにくそうな場合は「2,980円・5,980円・9,800円の3段階で用意しているのですが、どのあたりが現実的そうですか」と選択肢を提示して答えやすくする。
- Q7(LINE利用料の分かりやすさ): 「込み料金」と「別途負担」の両方を軽く説明してから聞く(前提の説明なしでは回答しづらいため)。
- Q8(AI対応への不安): 「誤予約」「お客様の反応」の2つを例示語として挙げ、回答が広がりすぎないようにする。
- Q9(オーナー確認を挟む運用): 「手間」か「安心」かの二択で一度受け、理由を追加で聞く形にすると時間短縮になる。
- Q11(導入障壁): 選択肢(操作の複雑さ/既存業務との相性/コスト/その他)を口頭で提示すると回答が早い。

## クロージング読み上げ台本(案)

> ありがとうございました。もしお時間に余裕があれば、もう数問だけ、無断キャンセル対策について伺ってもよろしいでしょうか(任意)。
> (時間切れの場合)本日は貴重なお話をありがとうございました。正式リリースの際には先行のご案内をさせていただきます。

## リハーサルでの確認ポイント(実施前チェックリスト)

- [ ] 基本セット(A〜D)が実際に12分前後で収まるか(社内で聞き手・回答者役に分かれて時間計測)
- [ ] Q5・Q8・Q9で想定より時間がかかっていないか
- [ ] E.(任意設問)に移った場合、合計時間が15分をどの程度超過するか(超過許容ラインを事前に決めておく)
- [ ] 台本を読み上げずに自然な会話として進行できるか(棒読みにならないための練習)
