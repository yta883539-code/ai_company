# 厳守事項9a FAQ回答テンプレート(2026-07-30 22:58 UTC)

faq-escalation-boundary.md の残課題「9aの回答が登録情報の範囲を超えて
店舗側の意図しない断定に踏み込まないよう、回答テンプレートの範囲を厳密に定義する」への対応。
owner-settings-wireframe.md の「店舗FAQ情報」入力欄(住所・アクセス/駐車場/支払い方法)ごとに、
AIが実際に返してよい文面の型をここで固定する。tone-and-manner-guideline.mdの
基本方針(主語は「お店」、絵文字は控えめ、1メッセージ1用件)に準拠する。

## 設計方針

- テンプレートは「登録された値をそのまま埋め込むだけ」の穴埋め式とし、AIが値を言い換えたり
  推測で補ったりする余地を残さない(店舗が入力していない情報を断定するリスクを防ぐため)。
- 1つの質問には1つのFAQ項目のみで回答する(1メッセージ1用件の原則を踏襲)。
  複数項目にまたがる質問(例:「駐車場と支払い方法両方教えて」)は、該当する項目ごとに
  改行またはテンプレートを連結して返すが、未登録項目が1つでも混ざる場合はその部分のみ
  厳守事項6のエスカレーション文言に差し替える(全体を一律エスカレーションにはしない)。

## 項目別テンプレート

### 住所・アクセス
```
当店: ○○(登録された住所・アクセス文言をそのまま挿入)です。
```
- owner-settings-wireframe.mdの入力例(「○○駅から徒歩5分」等)は自由記述のため、
  オーナーが入力した文言をそのまま使う。AI側での経路案内・所要時間の言い換え生成は行わない
  (入力文言と実際の経路が食い違うと誤案内になるため)。

### 駐車場
```
[あり・台数入力ありの場合]
当店: 駐車場がございます(○台分)。

[なしの場合]
当店: 申し訳ございません、当店に駐車場はご用意しておりません。
```
- 「あり」だが台数が未入力の場合は、台数部分を言わず「駐車場がございます。」とし、
  台数を尋ね返された場合は6番のエスカレーションに振り分ける(未入力項目のため)。
- 近隣コインパーキングの案内など、登録欄にない付加情報は生成しない。

### 支払い方法
```
当店: お支払い方法は(チェック済みの項目をカンマ区切りで列挙: 現金/クレジットカード/電子マネー/QRコード決済)がご利用いただけます。
```
- チェックされている項目のみを列挙する。未チェックの手段について個別に聞かれた場合
  (例:「PayPayは使えますか」)は、llm-system-prompt-draft.md 厳守事項9aの既存ルール通り
  「対応可否は不明」と断定せず6番のエスカレーションに振り分ける。

### 未登録・一部未入力のケース(共通)
```
当店: 恐れ入ります、その点は担当者に確認のうえ改めてご案内いたします。
```
- 厳守事項6のエスカレーション時の返信文言として、上記を標準とする。
  「わからない」「不明」等の否定的表現は避け、確認中であることのみを伝える
  (店舗が本当は対応可能なのに誤って「対応不可」と伝わることを防ぐため)。

## 複合質問の処理例

```
顧客: 駐車場ある?支払いはカード使える?
当店: 駐車場がございます(3台分)。
当店: お支払い方法は現金、クレジットカードがご利用いただけます。
```
(駐車場・支払い方法とも登録済みの場合。1メッセージ1用件のため2通に分けて送信する想定。)

```
顧客: 駐車場ある?電子マネーは使える?
当店: 駐車場がございます(3台分)。
当店: 恐れ入ります、その点は担当者に確認のうえ改めてご案内いたします。
```
(駐車場は登録済みで直接回答、電子マネーが未チェックのため後半のみエスカレーション文言に差し替えた例。)

## 未検証の仮説(要検証)

- 複合質問を項目ごとに分割して複数メッセージで返す設計が、実際のLLM出力で安定して
  再現できるか(1回のAI応答で複数意図を正しく分離できるかは要テスト)。
- 「メッセージトーン(カジュアル/standard/フォーマル)」設定と、本テンプレートの文体
  (「当店」「ございます」等のstandardトーン想定)をどう出し分けるかは未設計。
