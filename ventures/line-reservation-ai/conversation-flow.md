# 会話フロー草案(顧客⇄AI)

## 1. 新規予約(空き確認→確定)
```
顧客: 来週の土曜の午後空いてますか?カットお願いしたいです
AI:  ご来店ありがとうございます!来週土曜(8/9)の午後ですと、
     14:00・15:30・17:00 が空いております。ご希望のお時間はございますか?
顧客: 15:30で
AI:  かしこまりました。8/9(土) 15:30〜 カットでご予約を確定いたします。
     お名前を教えていただけますか?
顧客: 田中です
AI:  田中様、8/9(土)15:30〜カットのご予約を承りました。
     前日にリマインドをお送りしますので、当日お待ちしております!
```

## 2. キャンセル・変更(MVPでは人間確認を挟む)
```
顧客: すみません、明日の予約キャンセルできますか?
AI:  かしこまりました。明日(8/2) 10:00〜のご予約のキャンセルですね。
     念のため店舗側でも確認しますので、少々お待ちください。
     (→ オーナーへ通知: 「田中様より8/2 10:00予約のキャンセル希望」)
AI:  (オーナー確認後)キャンセルを承りました。またのご利用をお待ちしております。
```

## 3. 曖昧な希望日時のすり合わせ
```
顧客: 今週どこかで空いてる時間ありますか?
AI:  今週ですと、
     ・8/1(木) 11:00 / 16:00
     ・8/2(金) 13:00
     ・8/3(土) 10:00 / 14:00
     が空いております。ご都合の良い日時はございますか?
```

## 設計メモ
- AIの返信は「候補提示→確定」の2ステップを基本とし、いきなり確定させない(誤予約防止)。
- キャンセル・変更は初期はオーナー通知+人間確認を必須にし、AI単独では確定させない(二重取消・トラブル防止)。
- 名前・メニュー・時間帯が揃うまでは確定メッセージを出さないようプロンプト側で制御する。
