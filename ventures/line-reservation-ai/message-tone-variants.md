# メッセージトーン(カジュアル/standard/フォーマル)の出し分け設計

tone-and-manner-guideline.md 基本方針4で「owner-settings-wireframe.md の営業情報設定で
『メッセージトーン(カジュアル/standard/フォーマル)』を選べるようにし、テンプレートを出し分ける想定」
としていたが、実際にどの文言をどう出し分けるかは未設計だった(同ファイル「未検証の仮説」、
faq-response-templates.md「未検証の仮説」で共通の残課題として指摘済み)。本ドキュメントでこの出し分けを設計する。

## 前提: 3トーン共通で変えてはいけないもの

tone-and-manner-guideline.md・faq-response-templates.mdの既存ルールのうち、誤解・トラブル防止に
直結するものはトーン設定に関わらず固定する(トーンは「言葉づかいの丁寧さ」の調整のみに限定し、
業務ロジックに影響する語彙は対象外とする)。

- 「仮押さえ」「確定」という語は言い換えない(tone-and-manner-guideline.md 基本方針2)。
- 日付「8/9(土)」・時刻「15:30〜」の表記形式(基本方針6)。
- FAQ回答テンプレートの実質情報(住所・駐車場台数・支払い方法の登録値そのもの)は
  そのまま埋め込む(faq-response-templates.mdの穴埋め式ルール)。トーンで変わるのは
  それを包む前後の言い回しのみ。
- 1メッセージ1用件、催促は1回のみ、といった構造上のルール(基本方針3・5)。

## トーン別の言い回しルール

| 観点 | フォーマル | standard(既定) | カジュアル |
|---|---|---|---|
| 語尾 | 「〜いたします」「〜ございます」に加え「〜差し上げます」「〜くださいませ」等、より改まった言い回しを使う | 既存テンプレート通り(「〜いたします」「〜ございます」) | 「〜します」「〜しますね」「〜です!」など柔らかい言い切り。体言止めも可 |
| 絵文字 | 使用しない | 業種の既定に委ねる(既定は使わない。基本方針4の「店舗ごとに1〜2種類まで」は主にカジュアル向けの規定として扱う) | 店舗が設定した絵文字を1メッセージにつき1個まで使用可(乱用しない) |
| 感嘆符「!」 | 使用しない | 基本的に使用しない(「当日お待ちしております!」のような既存の1件は例外として残すが新規追加はしない) | 1メッセージにつき1つまで使用可 |
| 一人称の呼称 | 「当店」で統一 | 「当店」で統一 | 「当店」またはお店側が設定した店名の愛称(例: 「〇〇サロン」)を使用可 |
| 文の長さ・改行 | 用件ごとに改行し、やや丁寧な前置きを1文添える | 既存テンプレート通り | 前置きを短縮し、要点を先出しする |

## テンプレート別の書き換え例

### 予約確定メッセージ(tone-and-manner-guideline.md)

- フォーマル:
  ```
  当店: ご予約を確定いたしました。
      8/9(土) 15:30〜 カット / ○○様
      前日にご案内のご連絡を差し上げますので、当日はお気をつけてお越しくださいませ。
  ```
- standard(既存のまま):
  ```
  当店: ご予約を確定いたしました。
      8/9(土) 15:30〜 カット / ○○様
      前日にリマインドをお送りしますので、当日お待ちしております!
  ```
- カジュアル:
  ```
  当店: ご予約確定しました🙌
      8/9(土) 15:30〜 カット / ○○様
      前日にリマインドしますね、当日お待ちしてます!
  ```

### 前日リマインド(tone-and-manner-guideline.md)

- フォーマル:
  ```
  当店: 【リマインド】明日 8/9(土) 15:30〜 カットのご予約を承っております。
      ご都合が変わりました場合は、このトークにご返信くださいませ。キャンセル・変更を承ります。
  ```
- standard(既存のまま):
  ```
  当店: 【リマインド】明日 8/9(土) 15:30〜 カットのご予約です。
      ご都合が変わった場合は、このトークにご返信いただければキャンセル・変更を承ります。
  ```
- カジュアル:
  ```
  当店: 【リマインド】明日 8/9(土) 15:30〜 カットのご予約です🙌
      予定変わったら、このトークに返信でキャンセル・変更できますよ!
  ```

### 仮押さえ直後(pending-timeout-ux.md 1.)

- フォーマル: 「8/9(土) 15:30〜 カットで仮押さえいたしました。お名前を教えていただけますでしょうか。
  (5分以内にご返信くださいますよう、お願い申し上げます)」
- standard(既存のまま): 「8/9(土) 15:30〜 カットで仮押さえいたしました。お名前を教えていただけますか?
  (5分以内にご返信いただけますと確実にご予約いただけます)」
- カジュアル: 「8/9(土) 15:30〜 カットで仮押さえしました!お名前教えてください(5分以内にお願いします🙏)」

### FAQ回答テンプレート・駐車場あり(faq-response-templates.md)

- フォーマル: 「当店: 駐車場をご用意いたしております(〇台分)。」
- standard(既存のまま): 「当店: 駐車場がございます(〇台分)。」
- カジュアル: 「当店: 駐車場ありますよ(〇台分)!」

上記4パターンで確認した通り、変換規則は「語尾の丁寧度・絵文字・感嘆符の3点を機械的に置き換える」
だけで成立しており、実質情報(日付・時刻・台数・金額等)や「仮押さえ」「確定」等の固定語彙は
一切変更しない。この規則性により、新しいメッセージテンプレートを追加する際も個別にトーン別文言を
作り込まず、standardの文言に対して上記ルール表を機械的に適用するだけでフォーマル/カジュアル版を
導出できる(実装時はテンプレート内の可変ルール部分に3トーン分の語尾・絵文字有無をパラメータ化する
想定。詳細な実装方式はtech-stack.md側の課題として残す)。

## owner-settings-wireframe.mdへの反映

営業情報設定ページに「メッセージトーン」の選択欄(カジュアル/standard/フォーマル、既定はstandard)を
追加した(本ドキュメントの規則に基づき、店舗全体で1つのトーンを選ぶシンプルな設計とする。
メッセージ種別ごとに異なるトーンを設定する要望が出た場合は将来の拡張課題とする)。

## 未検証の仮説(要検証)

- tone-and-manner-guideline.mdで既に指摘の通り、業種だけでなく店主の個性による好みの差が大きい可能性があり、
  3段階の粒度で店舗ニーズを十分カバーできるかは実店舗の反応を見ないと分からない。
- カジュアルトーンの絵文字1個までというルールが、複数メッセージにまたがる一連の会話で
  くどく感じられないか(例: 確定メッセージとリマインドの両方に毎回絵文字が付くと過剰に見える可能性)。
- LLMが構造化出力の生成と同時に、店舗設定のトーンに応じた文言のブレなく安定して
  語尾・絵文字を出し分けられるかは、実LLM呼び出し(pending-approval.md参照、未承認)後でないと検証できない。
